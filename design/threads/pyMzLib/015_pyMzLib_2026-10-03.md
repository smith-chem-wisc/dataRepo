## pyMzLib 0.3.0: the new functions

Every example on these guide pages now runs in CI, against output recorded from the real bridge on
mzLib's own test data. So the code you copy from a guide is code that has run. Each guide opens
with a table of question, function, and the mzLib type that does the work. Each ends with what to
cite.

### `pymzlib.stats`: differential abundance, with no R (#71; mzLib #1341, #1357)

```python
fit = pymzlib.stats.fit("log2_intensities.tsv", "design.tsv", ["age"], trend=True)
q   = pymzlib.stats.adjust([0.01, None, 0.20])              # BH; None = untested
mm  = pymzlib.stats.meta([("P02768", 0.31, 0.08), ...])     # (feature, estimate, se)
```

- **`fit(responses, design, coefficients)`** runs one linear model per feature. It then gives
  limma's empirical-Bayes moderated t for each coefficient you name, with Benjamini-Hochberg
  applied per coefficient. This is limma's `lmFit` then `eBayes(legacy = TRUE)`, and mzLib
  reproduces limma 3.68.5 to within 1e-8 relative.
  - **Inputs.** `responses` is a TSV with one feature per row and one sample per column; blank,
    `NA` or `NaN` is missing, and **0 is an observation**. `design` is a TSV with one row per
    sample and one numeric column per coefficient. Add your own intercept column.
  - **Missing values are left out per feature, never imputed.**
  - **A feature that cannot be fitted is reported with its reason, never dropped.** The reasons
    are `too_few_observations` and `rank_deficient`; a feature seen in only one group cannot have
    a group effect.
  - **`trend=True`** is limma's intensity trend, for data whose low-abundance features are noisier.
  - **Check `residual_df_differ` before you compare with R.** When it is true, current limma
    (`legacy = FALSE`, its default) would give a different answer. That happens when missing values
    leave features with different residual degrees of freedom, which is the usual case in
    proteomics.
- **`adjust(p_values)`** is Benjamini-Hochberg over any list.
- **`meta(studies)`** pools one effect per study into a random-effects estimate per feature, by
  DerSimonian-Laird, and matches metafor 5.2.1 to 1e-8. Every row also gives
  `direction_agree` / `direction_disagree`, and how far the estimate moves when any one study is
  dropped. Those are the two things a reader of a pooled result asks first.
- **Guide:** https://smith-chem-wisc.github.io/pyMzLib/guides/stats/. It has two worked examples:
  agreement on limma's own reference output, and a real RNA dilution series whose answer is known.

### `proteins.annotate_go()` and `proteins.update_go()`: Gene Ontology on protein groups (#70; mzLib #1353, #1366)

```python
pymzlib.proteins.update_go("go.obo")                         # the only call that downloads
go = pymzlib.proteins.annotate_go(
    "AllQuantifiedProteinGroups.tsv", "the_search_database.xml",
    go_obo="go.obo", category_map="my_map.tsv", out="go_rows.tsv")
```

- **One row per (protein group, GO term)** that any member holds, directly or through an ancestor
  over `is_a` and `part_of`.
- **No member is privileged; there is no leading protein.** Each row names the members that carry
  the term, how directly, and on what evidence. So "every member agrees" and "direct annotation
  only" are filters on the table, not separate runs.
- **Every non-decoy group gets at least one row.** A group with no term gets a row whose
  `annotation_status` says why: `no_go_terms`, `no_entry` or `contaminant`. Missing GO is
  therefore visible, never a silent absence.
- **An isoform in the searched database inherits its UniProt entry's GO.** On PXD007188 that took
  0 inherited rows to 338.
- **`category_map=`** applies your own term-to-category map. mzLib ships no vocabulary of its own.
  `categories_out=` writes the per-category roll-up.
- **`out=`** writes the whole table with mzLib's own writer, with a provenance header. The writer
  is held byte for byte in the bridge tests. `limit` and `offset` window only what comes back to
  Python.
- **Reads any MetaMorpheus protein-group table:** `AllQuantifiedProteinGroups.tsv`,
  `AllProteinGroups.tsv`, or one file's `_ProteinGroups.tsv`. Decoys are skipped, and a group
  MetaMorpheus wrote twice is annotated once.
- **Real data:** five PXD036557 groups give 563 rows. mzLib's own run on a 715-group PXD036557
  table gave 87,513 rows in about 20 s.

### `sdrf.design()`: the label-free design an SDRF describes, or every reason it cannot (#69; mzLib #1363)

```python
d = pymzlib.sdrf.design("PXD067622.sdrf.tsv",
                        condition_columns=["factor value[treatment]"],
                        searched_files=raw_files, out="ExperimentalDesign.tsv")
if not d.is_valid:
    print(d.refusals)
```

- **One run per row**, in the 0-based coordinates that `flashlfq.quantify()` and
  `flashlfq.median_polish()` take. `.spectra()` and `.run_design()` hand them over.
- **A design MetaMorpheus would reject is refused, with every reason listed at once.** You never
  get a partial design. MetaMorpheus itself skips quantification on a bad design with only a
  warning, so a refusal here is the cheaper place to learn it.
- **Study-wide replicate numbers are renumbered within each condition** (control 1-3, treated 4-6
  become 1-3 and 1-3), and `notes` records every renumbering.
- **`searched_files=`** limits the design to the runs one search actually read.
- **`out=`** writes MetaMorpheus's 1-based `ExperimentalDesign.tsv`. Nothing is written for a
  refused design.
- **Real deposits:** PXD067622 gives 24 runs, 8 conditions with 3 replicates each. PXD049018 is
  refused, with 20 reasons.

### `isobaric.kits()`: every isobaric kit, with each channel's reporter m/z (#69; mzLib #1375)

```python
k = pymzlib.isobaric.kits("TMT6-plex")
```

- **Kits:** TMT 6/10/11, TMTpro 16/18, iTRAQ 4/8 and DiLeu 4/12. Labels are spelled as MetaMorpheus
  spells them. The m/z is theoretical at charge 1, derived from mzLib's `TMT.txt`, with mzLib's
  0.003 Da matching window.
- **Look a kit up by its MetaMorpheus modification name.** A partial name such as `"TMT10plex"` is
  refused rather than guessed. MetaMorpheus's own `Contains` chain used to accept it.

### Readers: RNA quantification tables, and protein-group tables without quantification (#68; mzLib #1388, #1365)

- **RNA tables.** An RNA search's `AllQuantifiedTranscriptGroups.tsv` reads through
  `read_protein_groups()` and `read_occupancy()`, and its `AllQuantifiedOligos.tsv` through
  `read_quantified_peptides()`. The columns keep their protein names: `protein_group_name` is the
  transcript group, and `sequence` is the oligonucleotide.
- **Protein-group tables from searches without quantification now read.** That is
  `AllProteinGroups.tsv` and each file's `_ProteinGroups.tsv`. They have spectral counts and no
  intensities, so `intensity` is in `absent_fields`. That means "no basis", not zero.

## Things that give a different answer from the same file

These are listed with their mzLib PRs on https://smith-chem-wisc.github.io/pyMzLib/upgrading/.

- **`pro_forma` writes `[UNIMOD:n]` for four shipped modifications** that it used to write by name
  (mzLib #1328): `GG (Ubiquitination Site)` is `[UNIMOD:121]`, both `Myristoylation` entries are
  `[UNIMOD:45]`, and `EQIGG` is `[UNIMOD:846]`. Masses are unchanged. **A string key built from
  `pro_forma` changes for every peptidoform carrying one of these.** Before this release, a pipeline
  keyed on Unimod silently dropped every ubiquitination site.
- **Terminal ProForma modifications read back on their own residue** (mzLib #1376). This matters
  when you read ProForma *into* mzLib. Before, 41 of 121 terminus-restricted modifications came back
  on a different residue: `Myristoyl on G` came back as `Myristoyl on C`. The masses were always
  right, which is why no number noticed. Now 0 of the 121 do.
- **A read fault on an existing `.mzid` is a `BridgeError` of type `MzLibException`** that names the
  file (mzLib #1362). It used to be an `IOException`.
- **PRIDE download errors name the file and the host, never the URL** (mzLib #1350). They are still
  `ServiceUnavailableError` in Python.
- **`formats()` lists two more file types**, for the RNA tables (mzLib #1388).

**Also fixed in pyMzLib:**

- **`flashlfq.median_polish(path)` with no design no longer hangs in a terminal or a notebook**
  (#73). The bridge reads an optional design from stdin, and with nothing to send it inherited
  yours. No bridge call does that any more.
- **`pride.list_ftp_files()` raises `ProjectNotFoundError` only for a missing project.** It used to
  re-map every error, including a too-deep FTP listing, to "no such project".
- **`pride.download_files()` accepts a selection file that starts with a UTF-8 BOM.** The first name
  used to fail as "not in project", after every other file had downloaded.

## mzLib 1.0.593: for C# callers (PXReprise, and anything else built on the NuGet package)

1.0.593 has 26 PRs, by @Alexander-Sol, @nbollis and @trishorts. The full notes are at
https://github.com/smith-chem-wisc/mzLib/releases/tag/1.0.593. Four changes can break existing C#:

1. **Eight more DLLs ship in the package.** They are `StatisticalModels.dll`, plus seven `PdfPig`
   0.1.16 assemblies (Apache-2.0, managed only). They land in every consumer's build output. If you
   ship a hand-listed installer or container manifest, add them.
2. **`SdrfSample.BiologicalReplicate`, `SdrfAssay.TechnicalReplicate` and `SdrfAssay.Fraction` are
   `int?`** (#1378). `null` means nobody established the value, and the builder writes
   `not available`. **Code that reads one into an `int` stops compiling**, and binaries built
   against 1.0.592 must be rebuilt.
3. **`IsobaricMassTag` and `IsobaricMassTagType` are now mzLib types in `Omics.Modifications`**
   (#1375). A file that imports both that namespace and MetaMorpheus's `EngineLayer` and names
   either type fails with `CS0104`. Add a using-alias, as MetaMorpheus #2860 did.
4. **`PrideArchiveClient` reports every transport failure as `HttpRequestException`** (#1350). A
   dropped connection mid-download used to throw a bare `IOException`, and a header timeout threw
   `TaskCanceledException`. **A `catch (IOException)` or `catch (TaskCanceledException)` around a
   download no longer sees them.** `StatusCode` is now set on every non-success response, so a 403
   can be told from a 503 without parsing text. Your own cancellation is still
   `OperationCanceledException`, and a local `.partial` write failure is still `IOException`.

**New in mzLib**, beyond what pyMzLib now projects:

- **`MedianPolishRollUp` and `MaxRollUp`** for the Quantification engine (#1399). With them it
  reproduces FlashLFQ's peptide and protein intensities exactly on the K562 test files: all 708
  peptide values, with and without match-between-runs. FlashLFQ's own results are unchanged.
- **`EuropePmcClient`** (#1373) finds a PRIDE project's paper, and downloads its JATS full text and
  supplementary zip. A download folder acts as a cache. It is not yet in pyMzLib (see below).
- **`.mzid` reads stream from disk** (#1362). A 20 MB file allocated 92.5 MB to read and now
  allocates 5.2 MB.
- **Linux builds include `PepXML.dll`** (#1364). It was dropped on case-sensitive file systems.
- **SDRF drafting** from raw-file names, papers and supplements (#1351 and others) is in this
  release, but it is all `internal`, so no package caller can reach it yet. We are keeping it that
  way until it has a named outside caller.
