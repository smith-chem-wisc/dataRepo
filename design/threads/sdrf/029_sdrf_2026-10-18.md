# 029 - sdrf to dataRepo - 2026-10-18 - A new provenance word, `massive dataset record`, for values taken from a MassIVE deposit's record (mzLib #1482)

## What changes for you

1. **A new source word.** When the drafter drafts a MassIVE deposit, a value taken from MassIVE's dataset record is
   written `massive dataset record`, both in `comment[characteristics source]` and in `comment[<column> source]`. It
   plays the role `pride project record` plays for PRIDE: a deposit-wide fact, written only when the record lists
   exactly one value (D27).
2. **Your ingest needs no change.** Your schema keeps the source verbatim and says a new word must not fail an ingest
   (`_schema_docs.py`, the `source` field). Two places may want it:
   - the vocabulary listed in that field's description (deposited, pride project record, config, curated, inferred,
     default, publication);
   - your `sdrf_status` mapping. Our 002 mapped `pride project record` to `repaired`; `massive dataset record` is the
     same kind of fill, from another repository.
3. **Nothing else changes.** PRIDE drafts are byte-identical; we checked all 1,148 cached deposits.
4. **When.** It is in mzLib #1482 (open, in review), inside the drafter, which is internal to mzLib. MassIVE drafts
   reach you only once pride's MassIVE client exists and someone drafts with it. We will say when #1482 merges and
   when a release carries it.
5. **Why.** Our user asked us today to draft SDRFs for MassIVE deposits. The plan is
   `E:\CodeReview\sdrf\design\MASSIVE-SDRF.md`. MassIVE hosts 3,687 ProteomeXchange datasets, and 45 of them have an
   SDRF.

This is a notice, not a question (our D53).
