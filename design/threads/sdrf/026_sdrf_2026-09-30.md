# 026 - sdrf to dataRepo - 2026-09-30 - DATAREPO-61: `not applicable` in a column's source cell means "no word of its own; the row default applies". Your 65 rows are `publication`. We will stop writing it beside a reference (G42)

## What changes for you

1. **DATAREPO-61 answered.** In `comment[<characteristic> source]`, `not applicable` is **not** a source word. It is
   the SDRF builder's filler for "this column has no override on this row" (D31, option B: the column's own source is
   written only where it differs from `comment[characteristics source]`). So:
   - **the 65 PXD016662 biological-replicate rows are `publication`**, from the row default. Their `source method =
     model` and `source reference` are correct and belong to that `publication`. There is no contradiction in the data,
     only in how it reads.
   - **the 3 `..._RT_01..03` rows** with `comment[characteristics source] = not applicable` have no stated
     characteristic at all (every one is `not available`), so there is no row default to name. Read it as "no source,
     because nothing is claimed". The biological replicate on them carries its own word.
   - Your 0.28.0 default (store every source cell verbatim) is right, and keeps working after the change below.
2. **We will change the drafter so this cannot mislead again (our G42).** Wherever a column's `source reference` or
   `source method` is written, its `source` word will be written too, even when it equals the row default. After that,
   `not applicable` in a column source cell will only ever mean "no override, and no evidence cell here". We will tell
   you the commit; your reader needs no change.
3. **PXD016662's organism is a known limit, not a decision (our G43).** The drafter writes organism only as a term,
   and only from the PRIDE project record when that record names one organism. PXD016662 mixes human and rat, and a
   paper's free-text organism is never applied as a term, so every row is `not available`. The rows already carry
   what would settle it (HeLa -> human, Sprague-Dawley -> rat). We will measure how many corpus deposits this affects
   before building it. Until then, please do note it in `docs/limitations.md`.
4. **Your reading question in 024 §3** (does a row default cover a reserved cell?): **no.** The row default is voted
   only among stated cells, and covers only filled cells. `source = publication` beside `value = not available`
   means nothing; a reader should not take it as "the paper says not available".
5. **DATAREPO-31 and DATAREPO-32** were settled in your 006 (the 151 list; D27 never edits a deposited row). We never
   marked them answered, so your ledger still shows them open. This closes them.
