# 032 - sdrf to dataRepo - 2026-10-27 - Two new provenance column families for conditions and sample names from evidence: `comment[factor value <factor> source]` and `comment[source name source]` (mzLib #1483)

## What changes for you

1. **Two new provenance column families, written only when evidence states the value.** mzLib #1483 (in review,
   `abbe14cd1`) now says where a drafted condition or sample name came from, the way it already did for
   characteristics, fraction and technical replicate:
   - `comment[factor value <factor> source]`, for example `comment[factor value condition source]`, with
     `comment[factor value <factor> source reference]` and `... source method]`;
   - `comment[source name source]`, with `... source reference]` and `... source method]`.
2. **When they appear.** Once evidence (a deposit's design table, a paper) states a condition or sample name on any
   row, every row that has one gets the source word: `deposited` or `publication` with its reference and method,
   or `inferred` for a value read from the file names. A cell nothing states has no source (`not applicable`).
   **A draft without evidence writes none of them**, so every PRIDE draft is byte-identical to before (1,148 checked).
3. **Why `factor value` is in the name.** An SDRF can have both `characteristics[disease]` and
   `factor value[disease]`, and `comment[disease source]` already belongs to the characteristic.
4. **The improver** writes the same columns for the factors it adds and the rows it drafts. It fills a deposited
   `source name` only where the deposit's cell is missing, and only from evidence. The deposit's own name is never
   replaced.
5. **Also fixed in the same review** (nbollis): a result table or figure data is no longer read as a design table; a
   replicate column that is `0`-based, `1.0` or mixed gives no claim instead of sample names; and `nd`, `unknown` and
   `?` are no claim. On the 117 MassIVE deposits with a curated SDRF, no draft changes.
6. **When.** Through drafts only, after #1483 merges and a release carries it. We will say when.

This closes our gap G53 (factor values had no provenance). A notice, not a question.

For your ingest: each family has the same three parts your schema already keeps per column (`source`, `source_reference`, `source_method`). The column names are new, so a column-name allow-list would need them.
