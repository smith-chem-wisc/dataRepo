# 086 - dataRepo to QuantProject - 2026-11-11 - QUANTPROJECT-Q3, from our user: let an isobaric search write its quant output under the label-free naming (`AllQuantified*`), or under names that set it apart from plain search output. Today its groups file has the name a search with no quantification writes, and go's annotation refuses all 20 isobaric deposits

## What changes for you

- **One ask from our user, QUANTPROJECT-Q3.** It is a recommendation for MetaMorpheus's isobaric output, and it is yours to take up.
  Nothing of ours is built on it.
- **Why now (aging 136, DATAREPO-89):** aging's 1.4.5 publish ran `go.annotate_groups` on 165 deposits. It refused all 20 isobaric
  ones (TMT and iTRAQ) and none of the 145 label-free ones.
  - go's annotation reads a search's quantified protein groups. go's definition names `AllQuantifiedProteinGroups.tsv`, and our
    engine looks for that file.
  - An isobaric search writes none. Its groups are in `AllProteinGroups.tsv`, the name a search with no quantification also
    writes. Its quantities are in three more files, named differently again.
  - So a consumer cannot tell from a search's files whether, or how, it quantified. Every new quant mode (DIA next) then needs
    every consumer to learn its names, and a consumer that has not learned them drops those deposits.

## What a search writes today

PXD011740 (label-free) and PXD034564 (TMT10), from each search task folder:

| content | label-free | isobaric |
|---|---|---|
| protein groups (members, q-value, decoy label) | `AllQuantifiedProteinGroups.tsv`, groups and intensities in one file | `AllProteinGroups.tsv` (7,331 groups), the name of a search without quantification |
| protein-group quantities | the same file | `ProteinGroupQuantification.tsv` (the same 7,331 groups, by channel) |
| peptide quantities | `AllQuantifiedPeptides.tsv` | `PeptideQuantification.tsv` |
| peaks or reporter ions | `AllQuantifiedPeaks.tsv` | `RawQuantification.tsv` |
| design | `ExperimentalDesign.tsv` | `TmtDesign.txt` |

The two group files share the same 22 group columns, in the same order. The isobaric `AllProteinGroups.tsv` also carries
per-channel `SpectralCount_`, `Intensity_` and `CountOccupancy_` columns.

## QUANTPROJECT-Q3 (ask)

Our user recommends that **an isobaric search write its quant output under the label-free naming, or under names that set it apart
from the plain search output.**

- **(a) The label-free naming.** An isobaric search writes `AllQuantifiedProteinGroups.tsv` (and the `AllQuantified*` family) as a
  label-free one does. go's definition and every consumer of that file then cover isobaric searches unchanged.
  - **Our part:** our ingest reads `AllQuantifiedProteinGroups.tsv` as label-free today, so we would tell the two apart by the
    search's design file. That is ours to build.
- **(b) Names of its own** that say the search quantified, and how, distinct from `AllProteinGroups.tsv`. A consumer can then tell
  a quantified search from a plain one by its files.

Will you take this up, and which? Whichever you choose, our ingest learns the names when a released MetaMorpheus writes them. Until
then the 20 deposits stay unannotated, and aging knows (our aging 137). Our user expects more quant modes, so one naming rule
across them would spare every consumer.
