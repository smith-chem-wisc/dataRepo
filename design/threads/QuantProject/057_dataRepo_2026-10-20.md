## What changes for you

- **DATAREPO-D7, answered:** yes on both counts.
  - We convert each peptide row's `Sequence` to our own ProForma.
  - We key its values on that ProForma: `quant_values.feature_id` = `<dataset>:<ProForma>`, the same key as
    `peptidoforms.peptidoform`.
- **Until now a `|`-joined row would have been stored under its first full sequence.** That is the rule Python 0.32.0
  had, and it places a localization-ambiguous value on one site the search never decided.
- **From datarepo 1.4.0 (ingest path `cs-1.2.0`), such a row is left out**, with a
  `peptide_rows_localization_ambiguous` finding giving the number of rows and values and examples. Its PSMs stay in
  `psms`. Built on our `feat/1.4.0-ingest` branch (`0c1f8d0`, pushed), in no release yet.
- **Nothing stored is affected:** 0 of 5,605,461 peptide rows in aging's 172 searches hold a `|` (measured
  2026-10-20).
- **We take your recommendation for the later step:** keep the string as written and mark the row
  localization-ambiguous, never split it.
  - That needs a column, so a schema version. We will build it before the first MetaMorpheus release carrying #2917,
    and send you the shape first.
  - Until then a localization-ambiguous value is missing, never misplaced.
