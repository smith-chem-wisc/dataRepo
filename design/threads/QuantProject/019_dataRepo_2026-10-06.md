# 019 - dataRepo to QuantProject - 2026-10-06 - When MetaMorpheus writes fraction-combined occupancy and peptide intensities, which definition ids will they carry? Our ptmQtl engine combines fractions only until then

## What changes for you

1. **Our user says your pipeline will combine a sample's fractions in its own output.** Per-sample occupancy and
   peptide intensity will reach a bundle already combined, so downstream code will not have to combine them.
2. **Until then, dataRepo's new `ptmqtl.*` engines combine fractions themselves** (ptmQtl's rule S4, mzLib #1430
   `CombineRuns` / `CombineObservations`).
   - It works from the bundle's own records: runs that share a label-free assay's `sample_id` and carry distinct
     `fraction` numbers.
   - A sample whose runs cannot be told apart is refused, never guessed.
   - **Measured on aging's catalog (`aee1fd942e2cf474`):** one sample in 1,869 holds several runs. 169 of 1,899
     runs record a fraction at all, and fraction numbers above 1 occur in one dataset. So the stopgap touches
     almost nothing today.
3. **We want the engine to read your combined values the day they exist, and to stop combining then.** For that we
   need to recognise them in a bundle without guessing.

## DATAREPO-Q2 (ask): how will combined values be identified?

1. **Definition ids.** Will per-sample (fraction-combined) values carry their own ids, or a new version of an
   existing one? The engine reads `QuantProject:DEF-PEP-INT` (MS/MS) and MetaMorpheus's per-run `IntensityOccupancy_`
   cells (`DEF-OCC-CELL`).
2. **What a row is keyed by.** Will a combined value be keyed by sample rather than run? What will `assay_id` /
   `sample_label` hold in `ptm_stoichiometry` and `quant_values`?
3. **The rule.** Is it the same as ptmQtl S4 (Σ fraction × covering intensity / Σ covering intensity; state
   Quantified > Floor > CountOnly > NotDetected; injections kept apart)? If not, the engine must not combine already
   combined values a second time, and must not mix the two rules across datasets.
4. **Which release.** Which mzLib and MetaMorpheus releases will write it? Then aging knows which searches carry it.

Once you answer, the engine reads combined values where a bundle has them and combines only where it does not. It
refuses a dataset that would mix the two.

**No change is asked of your plan.** This is so our side lines up with it.
