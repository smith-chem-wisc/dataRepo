## DATAREPO-D3: what we store, measured on PXD001054

Measured on PXD001054, the newest stored bundle (`2d48659d3a0df9a7`):

| the engine needs | stored? | where |
|---|---|---|
| each peptide value's file | yes | `quant_values.assay_id` -> `assays.run_id`: one label-free assay per run |
| the value (`DEF-PEP-INT`) | yes | `quant_values`, `feature_type = 'peptidoform'`, `definition_id = 'QuantProject:DEF-PEP-INT'`: 41,530 values |
| MS/MS or MBR (`DEF-PEP-DT`) | yes | `quant_values.detection_type`: 27,327 `MSMS`, 14,203 `MBR` |
| whether an MBR value passed `DEF-MBR-KEPT` | yes | `quant_values.mbr_kept`, with `pip_q_value`, on every MBR row; NULL on MS/MS rows |
| each group's decoy/contaminant/target flag | yes | `protein_groups.target_decoy`: 1,177 target, 16 contaminant, 159 decoy |
| each group's `Protein QValue` | yes | `protein_groups.q_value`, on all 1,352 groups |
| the group(s) a peptide belongs to | **in part** | `peptidoforms.protein_group_id`, only when the peptide's accessions are exactly one group's members: 6,427 of the 7,161 quantified peptidoforms. The other 734 are shared across groups. Their `protein_accessions` lists the accessions, but not the groups MetaMorpheus named |
| whether a peptide is unique to one group | **no** | no column |

- **`peptidoforms.is_unique` is not group-uniqueness.** It is gene-uniqueness from the searched sequences: every
  protein whose sequence contains the peptide belongs to one gene (mzLib `PeptideUniquenessClassifier`; our D40). A
  peptide can be gene-unique and shared between two groups of one gene's isoforms.
- **Our recommendation for M7:** take group membership from the `Protein Groups` column of the search's
  `AllQuantifiedPeptides.tsv`, through your #1455 builder. Do not rebuild it from our accession lists.
  - Each bundle's `bundle.json` lists that file under `sources`, role `peptide_quant`, with its path and sha256.
  - If the file has moved or changed since ingest, the engine refuses rather than computing from a different search.
- **Storing membership ourselves would mean a new core table and a re-ingest of every deposit.** We would rather not,
  unless reading the file turns out not to work. If it is needed, it rides the 1.4.0 re-ingest that is already planned.
