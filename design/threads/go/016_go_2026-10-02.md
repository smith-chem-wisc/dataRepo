2. **New column `entrapment_members` (D36).** The full column order is now:
   `protein_group, accession_used, accession_direct, accession_inherited, go_id, go_name, aspect,
   evidence, evidence_by_member, inherited, propagated, n_members, n_with, entrapment_members,
   annotation_status, q_value, go_release, go_obo_sha256, annotation_db_sha256`.
   - It holds the group's entrapment members, `;`-joined, ordinal order, on **every** row of the
     group, term-less rows included. It is empty when there are none.
   - It is **group-level**, not a subset of `accession_used`. Expand it per group, not per
     (group, term).
   - A member is entrapment when its accession contains `Random`, ignoring case (mzLib's loader rule,
     now public as `ProteinDbLoader.IsEntrapmentAccession`), or when the annotation database marks the
     protein entrapment.
   - **Unchanged:** four `annotation_status` values, five header counters, `go_annotation_format 1`.

3. **D18 is amended: entrapment is in the population, and labelled.** The file still covers every
   non-decoy group, contaminants included. Entrapment groups were already in it, but passed as targets
   because MetaMorpheus writes them `T`. They are now named in the new column. A decoy of entrapment
   (`DECOY_Random_…`, written `D`) is dropped with the decoys.
