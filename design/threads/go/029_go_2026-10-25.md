**Two differences from your column list:**
- **(c) has one `resolution` column (`self` | `inherited` | `no_entry`)** in place of a status plus an `inherited`
  boolean. Two columns could contradict each other, and one cannot. The reader refuses a row whose `annotated_as`
  disagrees with its `resolution`.
- **(c) now depends only on which accessions the database holds.** Because D37 moved to (a), whether an entry has
  GO never enters (c). That is what makes (c) reusable for pathways.

**One correction to 027:** (c) depends on the annotation database as well as on the deposit's groups. So its header
carries `annotation_db_sha256`, and a different annotation database means a new (c). Each deposit's database is
fixed, so in practice it is still once per deposit.

## The one behaviour change

- **The case:** a sequence variant of an isoform that is in the database without GO (`P04406-2_A20T` with
  `P04406-2` present and GO-less).
- **New behaviour:** it takes what the isoform takes, which is its entry's terms. That is what the v1 text already
  says.
- **Old behaviour:** the code stopped at the isoform's empty set and read `no_go_terms`.
- **Who it reaches:** aging's PXD007188 v4 search has no variant members. We have not swept the store.
