## GO-D7 (answer): per-member qualifiers, `e0df39b`

For each accession `a` expanded from a go row over `accession_used`:
- `inherited` = `a` ∈ `accession_inherited`;
- `propagated` = `a` ∉ `accession_direct`;
- `evidence` = `a`'s codes from `evidence_by_member`, `;`-joined like your `evidence` column. It is NULL if `a`
  has none.

`protein_group`, `q_value`, `n_members` and `n_with` stay group-level. No schema change; the three column
descriptions now say "this accession's".

**What we refuse.** We also check a row's per-member columns against the row itself. Any of these refuses the run,
because a per-accession row built from such a row would be wrong:
- a member in `accession_direct` or `accession_inherited` that is not in `accession_used`;
- `evidence_by_member` that does not cover exactly `accession_used`, or that has a malformed or repeated entry;
- a pooled `propagated` that is not (`accession_direct` empty);
- a pooled `inherited` that is not (`accession_inherited` = `accession_used`).

**Tested on your fixture file** (`fixture1347`, group `P0C0S5|Q71UI9`), whose members' evidence already
differs:
- **Your 023 example.** We edited a copy so that only P0C0S5 cites the term directly. P0C0S5's row reads
  `propagated = false` with `ECO:0000314;ECO:0000353`, and Q71UI9's reads `propagated = true` with
  `ECO:0000353`. Under the old reading Q71UI9's row had P0C0S5's directness and IDA.
- **Inheritance.** With Q71UI9 alone in `accession_inherited`, its row reads `inherited = true` and P0C0S5's
  reads false. Your pooled flag stays false.
- **Refusals.** Each one has a test.

Every cellular-component row of the unedited fixture passes these checks. They run only on the rows we
store, which are the cellular-component ones.

## GO-D9 (answer): one go.obo and one map per catalog, enforced

A catalog build is refused if its go artefacts used two go.obo files or two category maps, compared by sha256.
The refusal names which datasets used which.

When either file changes, the operator re-annotates every dataset with the same `--input`. A catalog that
mixes them cannot be built at all, so nothing else is needed. The UniProt annotation database stays per dataset
(GO-D5) and is outside the rule.

Each row also carries `go_release`, and each category row carries the map name and version.
