## 1. Entrapment: what 1.0.597 fixes and what it does not

- **The released generator gives go nothing to leak.** It writes a shuffled partner with no `dbReference` at all
  (`EntrapmentProteinGenerator.cs:525`, an empty list) and a foreign entry with its own (`:254`).
- **A database built before that fix still leaks.** #1271's heads before `c3400f00` copied the target's
  `dbReference`s, GO included, onto each shuffled partner (GO-E1). Released go still reads that GO. Your narrower
  check exists to catch this.
- **D39 is next.** It makes go ignore a shuffled partner's GO whatever the database, and it was waiting on #1271.
  - It has to be rebuilt, not replayed: #1497 moved every rule that reads an entry's GO into (a)
    (`GoAccessionAnnotation`).
  - It changes rows, so it ships under a new definition version, with a thread to you.
  - As 020 said, go posts the release number when it ships. **Until then, keep the check as a filter.**

## 2. What changed in #1497 after 030

| change | does it touch your files? |
|---|---|
| **Member resolution reads accessions with `VariantApplication.ParseAccession`** (mzLib's variant grammar). ProteinDbLoader's collision counter `P12345_2` names a **different entry** whose accession collided. It is no longer read as a variant of `P12345`. | **Yes, rows change.** Take a member `P12345_2` in a database that holds `P12345` but not `P12345_2`. It now reads `no_entry`; before, it inherited `P12345`'s terms. The same holds for the group-level `go_annotation.tsv`: 1.0.596's annotator used a looser regex (`GoGroupAnnotator.cs:211`). |
| **The strict (c) reader and writer refuse an inherited row that the grammar does not give.** (`P04406-2 -> Q13148` is refused, `P04406-2 -> P04406` is not.) | Only if your tests write (c) rows by hand. Use UniProt-shaped accessions. Rows the resolver writes always pass. |
| **`GoAccessionTermsTsv.Write` refuses an annotation without a database sha256.** Before, it wrote a file its own reader refused. | No |
| **A `GoGroupAnnotator` built from a resolver and an annotation of different databases throws `InvalidOperationException`**, naming the member. | No |

- **The definition stays `go:DEF-GROUP-GO-ANNOTATION v1`.** v1's text already says "a sequence variant in mzLib's
  grammar"; the old regex did not follow it. The 1.0.595 and 1.0.596 rows for such a member were therefore not v1
  rows. They came from a bug, and v1 itself did not change.
- **The fixture has no such member**, which is why it did not move.
- **We have not swept your store, but we expect few or none.** Only `LoadProteinFasta` adds a collision counter
  (`ProteinDbLoader.cs:373-384`), and only when one FASTA holds the same accession twice. The XML loader never adds
  one. So only a search that used such a FASTA can have one.
