## GO-D7 (still asked): per-member qualifiers

Unchanged from 023. For each accession `a` expanded from a go row, set:
- `inherited` = `a` ∈ `accession_inherited`;
- `propagated` = `a` ∉ `accession_direct`;
- `evidence` = `evidence_by_member[a]`.

Your `Sources/Go.cs:80-81` says the per-member columns are "checked by name and read, but not stored: storing
them is a schema" change. GO-D7 does not ask you to store them. It asks you to use them when you **derive** the
three per-accession values you already store. Please post the commit to both us and ptmQtl.

## GO-D9 (ask): one go.obo and one map per catalog

ptmQtl's GO-P2 asked whether a comparison across datasets can rely on one `go_release` and one map version. What
we told them:
- the go.obo and the map can be pinned;
- the UniProt annotation database is per dataset (your GO-D5: the searched target databases), so they record it
  rather than refuse on it.

**Asked:** that each catalog uses **one** pinned `go.obo` and **one** version of each category map, and that a
change to either re-annotates **every** dataset together. Re-annotation is cheap (34 s for PXD077298) and needs no
re-search. If you rule otherwise, tell ptmQtl and us. They will then refuse comparisons across mixed releases.

## GO-D10 (ask, a confirmation): group membership covers every non-decoy group

ptmQtl's GO-P1 is "never annotated" against "annotated, no GO term" per accession. For a target accession we
answered without a new column:
- **(a) never annotated:** the accession is in no non-decoy group of the stored table;
- **(b) annotated, no GO term:** the accession is in a group and has no `protein_localizations` row.

This relies on two things. go annotates every non-decoy group whatever its q-value (D29), and your annotation
database is the searched target database (GO-D5).

**Asked:** confirm that the catalog's protein-group membership table holds **every** non-decoy group of the
stored table, not only the groups at q <= 0.01. If it holds only the groups that pass, a group above the cutoff
reads as a false (a). Then either load them all, or tell ptmQtl the cutoff so they can apply the same one to both
sides.

We do **not** ask for a per-accession `annotation_status` column. If you add one, use go 002's rule, and only for
target accessions.
