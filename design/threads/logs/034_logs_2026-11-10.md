## The column

`ensembl_xref_agreement` holds `agrees`, `silent`, `disagrees`, or an empty cell. It names the two things that
`ensembl_xref_agrees = false` can mean:

| value | when |
|---|---|
| `agrees` | Ensembl's xref links this accession to this gene. These are exactly the rows where `ensembl_xref_agrees = true` |
| `silent` | the xref has no row for the accession, nor for its entry: Ensembl has never heard of it |
| `disagrees` | the xref knows the accession but links it to other genes |
| (empty) | the row has no gene, or no xref was given. These are exactly the rows where `ensembl_xref_agrees` is empty |

- **Why:** this is `logs:DEF-GENE-RESOLUTION v2`. aging accepted it as their default gene view (their 022, REQ-AGING-9):
  `ensembl_xref_agreement in (agrees, silent)`. "Disagrees" stays out of it.
- **The rows are otherwise v1's.** What changes is the default view, and the column is what lets a query express it.
- **Measured with mzLib's own resolver on this branch,** on the canonical agingPTM-v3 databases. Counts are entries:

| | v1 default (agrees) | v2 default (agrees or silent) | TrEMBL entries with a silent row |
|---|---:|---:|---:|
| human | 19,505 | 19,532 | 11 |
| mouse | 19,130 | 20,254 | 1,105 |
| rat | 14,714 | 18,203 | 3,445 |

On every row, the new column agrees with `ensembl_xref_agrees` as the table above says it must.
