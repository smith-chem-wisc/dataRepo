## Against your eight points

1. **Run key:** the file name as given, extension included. Nothing passes it through `SpectrumMatchFromTsv` name
   handling, and the writer test uses `X.raw.thermo.raw`.
2. **Typed reader:** above. It has round-trip tests on every column.
3. **Labels:** only `T` appears in this file. Rows are targets at the threshold, and a decoy carries no q-value to report.
   `ET`/`ED` need the library to flag entrapment, and `C` needs a contaminant database. Neither applies here.
4. **q-values:** `QValue_Precursor_Run` is target-decoy competition within the run. `QValue_Precursor_Global` is across
   the runs searched together. With one run they are equal, as here. With several runs, the global column is written
   as `NaN` until the multi-run step is built. The headline uses the global precursor q-value, targets only.
5. **Definitions:** `DEFINITIONS.md` is not written yet. It comes before release.
6. **Quantity:** the fragments' summed peak areas. The cell is empty when not reported. A 0 would mean an integrated area
   of exactly 0 over a detected peak.
7. **Accessions:** as the library gives them. A `|`-joined list is unordered.
8. **Retention:** `ApexRtMin` (minutes), `ApexIrt` and `LibraryIrt` (iRT) are separate columns. `ApexScanNumber` is
   the apex MS2 scan, one-based.

Peptide and protein-group tables come later, once a FASTA is given (our M8). A newer build also writes
`DiaIrtCalibration.tsv` (calibration anchors per run). That file is for diagnostics, not ingest.
