# 005 - dia to dataRepo - 2026-11-07 - The DIA peptide table has a typed reader in mzLib #1538; the protein-group table is MetaMorpheus's own format and needs none

## What changes for you

- **`AllDiaPeptides.tsv` now has its writer and reader in one class, mzLib `Readers.DiaPeptideFile`.** It was added to the open PR that carries the precursor reader, [mzLib #1538](https://github.com/smith-chem-wisc/mzLib/pull/1538), on 2026-11-07. As before, pyMzLib cannot reach it until #1538 is merged and released.
- **`AllDiaProteinGroups.tsv` is MetaMorpheus's protein-group format, column for column,** so it needs no new reader. Its name already resolves to `SupportedFileType.MetaMorpheusQuantifiedProteinGroups`, and mzLib's existing `ProteinGroupFromTsvFile` reads it. A test in #1538 pins that. If you ingest MetaMorpheus's DDA protein groups, the same code reads these.
- **Nothing is released yet.** The MetaMorpheus side is on our fork as draft PRs (the task is `trishorts/MetaMorpheus#39`). It goes to smith-chem-wisc once mzLib #1456 and #1538 are released.

## The peptide table, against your eight points (your 002)

One row per peptide (modified sequence) across the runs searched together; only target peptides at the q-value threshold.

| # | column | what it is |
|---|---|---|
| 0 | `Full Sequence` | MetaMorpheus notation |
| 1 | `Base Sequence` | |
| 2 | `Protein Accession` | the library's, `\|`-joined; the order means nothing (your point 7) |
| 3 | `Decoy/Contaminant/Target` | `T`/`D`/`ET`/`ED`/`C`, as in the precursor table |
| 4 | `Score` | the best score of the peptide's precursors over every run |
| 5 | `QValue_Peptide_Global` | target-decoy competition among peptides (each peptide's best precursor), across all runs |
| 6 | `File Name` | the run of that best precursor, exactly as deposited (your point 1) |
| 7 | `Precursor Charge` | that best precursor's charge |

- **Joining:** columns 6, 0 and 7 join a peptide to its best precursor's row in `AllDiaPrecursors.tsv`, which carries the apex scan number for a USI (your point 8).
- **First line:** `# contaminants: assessed` or `not assessed`, as in the precursor table. A file without it is refused, not read as "not assessed".
- **No quantity column.** Peptide and protein quantities come from mzLib's `QuantificationEngine`, which is our next milestone. They are not in this table.

## Contaminants: a correction

**Before this change, a contaminant database made both DIA tables say `# contaminants: assessed`, while no row could be labelled `C`.** That is exactly the false "no contaminants" your point 3 warned about. It was never released.

Now the task loads any protein database given beside the library. Precursors and peptides whose proteins are all in a contaminant database are labelled `C`; protein groups carry MetaMorpheus's own `C`.

## Protein groups

- **Inference:** inferred over all runs together, by MetaMorpheus's parsimony and picked protein FDR, unchanged. Only target groups at the threshold are written.
- **When it is not written:** the table needs a protein database beside the library, and decoys in the library that name decoy proteins (mzLib's library builder records them). Without such decoys, the task writes no protein table and warns, rather than writing q-values with no decoy evidence.
- **The q-value has a known defect:** we found it in MetaMorpheus's protein FDR, in DDA too. A target that loses to its own decoy could be written with q = 0. The fix is [MetaMorpheus #2957](https://github.com/smith-chem-wisc/MetaMorpheus/pull/2957), open. It moved 1-16 groups at 1% on our runs.
