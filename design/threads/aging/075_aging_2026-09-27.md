# 075 - aging to dataRepo - 2026-09-27 - `protein_accessions` is MetaMorpheus's PARSIMONY list, not every protein a peptide maps to, so `is_unique` calls a four-protein peptide unique. The data are right; the descriptions and one derived column are not

## What changes for you

1. **The stored values are correct.** They are MetaMorpheus's parsimony result, which is what a caller should get by
   default. Our user's statement of the rule, which we adopt:
   - one peptide shared by a canonical and an isoform gives an AMBIGUOUS group listing both;
   - if that peptide is seen WITH a peptide unique to the isoform, parsimony lists ONLY the isoform. Both forms may be
     expressed, but the data cannot say so.
   So a shared peptide can carry a single accession.
2. **Three things in the catalog describe or derive from it wrongly (REQ-DATAREPO-5):**
   - **(a) `peptidoforms.protein_accessions`** is described as "All protein accessions the peptide maps to".
     `protein_groups.protein_accessions` carries the same sentence, which does not fit a group either. Both are the
     parsimony-assigned accessions.
   - **(b) `peptidoforms.is_unique`** ("Maps to exactly one protein") appears to be computed from that reduced list.
     Please confirm from your ingester. If it is, it says `true` for shared peptides whenever parsimony picked one member.
   - **(c) `peptidoforms.is_isoform_specific`** is NULL on all 4,315,173 rows. That is already flagged, and is here for
     completeness.
3. **The case, verified at the source.** Catalog `8af306854043f771`, PXD028975:
   - `TGQEALSQTTISWAPFQDTSEYIISCHPVGTDEEPLQFR` has `protein_accessions = [P02751-13]` and `is_unique = true` (13
     peptidoforms at 1% FDR).
   - In the searched sequences it occurs in **P02751** (the reviewed human proteome, sha256 `760984e8…`) and in
     **P02751-1, P02751-8, P02751-13** (the D43 isoform database).
   - Parsimony chose P02751-13 because the dataset also holds an FN1 isoform-unique peptide: the EDB-skip junction
     `ESVPISDTIIP|AVPPPTDLR`, about 2,050 PSMs.
4. **What we ask:**
   - **(a) Describe both columns as parsimony-assigned.** This is text only.
   - **(b) Either** compute `is_unique` against the searched database, which `resolve_genes` and pyMzLib
     `classify_peptides` already read, **or** rename or redescribe it as "parsimony-unique". Your call; we need only
     one of the two to be true of the name.
   - **(c) Populate `is_isoform_specific` from the searched sequences, or drop it.** A NULL column that O-section
     questions filter on answers "no" silently.
   Nothing of ours waits on this. We compute specificity ourselves against the searched sequences
   (`results/organelle_isoforms_2026-09-26/`), and `ptm_sites` inherits parsimony exactly as we want.
5. **FYI, D59:** from today, NEW datasets are searched against PTM-annotated copies of the same reviewed proteomes and
   isoform databases (`*_agingPTM-v1.xml`). Entries and accessions are unchanged, and only `modified residue` features
   were added. The main database keeps its position as the first `-d`, so your "the search database" reading holds.
   Isoform sites were assigned by the parsimony rule above (225 sites).
