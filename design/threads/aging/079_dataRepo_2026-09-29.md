## 1 - The table

Key: (`sample_id`, `name`). `sample_id` must be a sample the catalog holds, and `build` refuses one
it does not.

| column | required | what it is |
|---|---|---|
| `sample_id` | yes | a core sample |
| `name` | yes | the SDRF header form: `characteristics[organism part]`, `[cell type]`, `[cell line]`, `[disease]`, `[sex]`, and so on. It is the same vocabulary as `sample_characteristics.name`, so one filter reads both |
| `value` | yes | the name as curated, or an SDRF reserved word (below) |
| `value_reserved` | computed | **we compute it** from `value`, using the core's SDRF list. Leave it empty. If you fill it and it disagrees, the write is refused |
| `term` | no | UBERON, CL, `CVCL_`, MONDO/DOID, or PATO:0000461 for normal |
| `source_reference` | yes | what the value was read from. A value whose source cannot be named is not delivered, as for a curated age |
| `evidence` | no | your note, verbatim |
| `confidence` | no | your `high` / `medium` / `low`, verbatim. It is not an enum, because the words are yours |
| `curation_version` | yes | e.g. `aging-curation/1`. It is a curation label, so it is never written into `normalizer_version` |

**Three different answers, three representations** (G42 from the curator's side):
- `not applicable` means the characteristic does not apply, e.g. the tissue of a cell line;
- `not available` means you read the sources and they do not say;
- no row means the characteristic was not curated.

Our first draft refused reserved words. Filling the table from your file showed that this merged the
second and third answers, so the release keeps them and flags them.

**A caller that stops at `samples` is told where to look.** When a `datarepo_sql` statement reads
`samples` or `sample_characteristics` and this table (or `sample_ages`) holds rows, the answer
carries `study_tables_on_these_samples`. So a NULL `samples.cell_line` no longer reads as unknown.
That is G69 one step later, and the note is in the envelope because `describe` can be skipped.

## 2 - The scratch fill (2026-09-29, not a delivery)

We took your `instance/samples/samples.tsv` at `f3524a6` and broadcast each dataset's values to every
sample in its stored bundles (all bundles of that PXD in `F:/aging_data/repo/store`). We wrote the
result as a study bundle in a scratch store. Nothing was written under `F:/aging_data`.

- **52 datasets, 1,188 samples, 8,316 rows.** The write succeeded: the format, key and required
  columns all hold on your data. 2,074 rows came out `value_reserved`.
- **(a) 40 of 52 datasets say `per_run_differs: yes`.** For those, broadcasting a dataset's value to
  every sample is wrong, and it is exactly what the table is per sample to avoid. Each needs one
  value per sample. Runs map to samples through the core `assays` table (`run_id` -> `sample_id`).
  For PXD036557, `QE-002106_GM1_a` is `PXD036557:PXD036557-Sample-1`. There, one sample is one
  injection, so GM1_a/b/c are three samples.
- **(b) 51 cells carry several answers in one cell.** For example, PXD036557's disease reads
  `Hutchinson-Gilford progeria syndrome (GM6-8); normal (GM1-3)`, and PXD032202's organism part
  reads `capsule of lens; eye trabecular meshwork; iris`. Each sample gets one of them, and the
  mapping goes into `evidence`.
- **(c) 33 `term` cells are not one term.** Some hold several (`UBERON:0001804; UBERON:0005969;
  UBERON:0001769`), which is (b) again. Some hold a word (`not applicable` in `cell_line_cvcl`). A
  term cell holds one CURIE or is empty.
- **(d) `not stated` appears 53 times.** It is not an SDRF reserved word, so it would be flagged
  `value_reserved = false` and counted as a cell line called "not stated". Write `not available`.
  (`not applicable`, 101 times, is already right.)
- 26 cells have a term and no name, for example a `CL:` id with `cell_type_name` empty. They load,
  but give the name too: `value` is the column a reader filters on.

We mapped `sample_kind` to nothing, because it has no SDRF header. If you want it stored, tell us
which header, or whether it belongs in the core `samples.material_type` (which only an SDRF fills
today). We have not built that.
