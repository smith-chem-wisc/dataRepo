# 092 - dataRepo to aging - 2026-10-06 - datarepo 1.2.0 is released: the go engine runs. Re-ingest on 1.2.0, not 1.1.0, and add one step, `run go.annotate_groups`, before the scratch catalog

## What changes for you

1. **datarepo 1.2.0 is published:** https://github.com/smith-chem-wisc/dataRepo/releases/tag/v1.2.0 (tag on
   `4e49846`). On this machine use `datarepo-1.2.0-win-x64.zip`. Its `doctor` prints `datarepo 1.2.0  schema 0.0.15`.
2. **Use 1.2.0 for the re-ingest in our 090, in place of 1.1.0.** The ingest path is still `cs-1.1.0` and the
   schema still 0.0.15, so the bundles are byte-identical to 1.1.0's and have the same ids. Nothing in 090 changes
   except the version.
   - **We read your store today: it holds no `cs-1.1.0` bundle yet**, so nothing has to be redone.
3. **New: the go engine runs** under go's published definition, `go:DEF-GROUP-GO-ANNOTATION v1` (go 023). This is
   what puts GO-CC terms and your organelle categories into the catalog: `protein_localizations` and
   `organelle_term_categories`. **Today no catalog holds a single go row.**
   - Each row describes its own accession (go GO-D7). In a multi-member group, `inherited`, `propagated` and
     `evidence` are that member's own. Before, go's group flags were copied onto every member. Your organelle
     claims built on `inherited = false` can use these rows as they stand.
4. **One rule you must keep (go GO-D9):** a catalog serves **one** `go.obo` and **one** category map. A build whose
   datasets were annotated with different files is refused and names them. To change either file, re-annotate
   every dataset. Re-annotating needs no re-search.

## Step 5: the command

The two input files are your choice. These are the ones on this machine, and they belong together: the map was
checked against this go.obo (`65e3332`).

```
datarepo run go.annotate_groups <PXD> --store <new store> --latest ^
  --input ontology=F:/aging_data/go/go.obo ^
  --input category_map=E:/CodeReview/aging/design/maps/aging-organelle-map_v1.tsv
```

- `go.obo` is `data-version: releases/2026-07-26`. The map is `aging-organelle-map` v1: 24 rows, 12 categories.
- **Run it one dataset at a time, in a loop.** Some datasets are refused, and a refusal ends the call it is in:
  - **an entrapment search** stays refused until go's D39 is in an mzLib release (go 018/020);
  - **an accession in two groups** stays refused until MetaMorpheus says whether parsimony can do it (our go 011).

  Each refusal names its reason. Please send us the list; we have not measured how many datasets it covers.
- go measured about 34 s per dataset (go 024), so roughly an hour for the corpus.
- A second run with the same inputs reports "already done" and writes nothing.
- The search databases come from each bundle's own record. Only target databases are used, never the contaminant
  panel (go GO-D5).
