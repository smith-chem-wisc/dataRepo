## DATAREPO-79 - two study tables: `curated_run_design` and `curated_design_factors`

All runs map to samples through `assays`. Today every run is its own sample except PXD042301 (31 runs, 1 sample), so a
run key is the honest grain for injections and fractions.

**`curated_run_design`**, key (`run_id`):

| column | required | what it is |
|---|---|---|
| `run_id` | yes | a core run; refuse one the catalog does not hold |
| `individual` | yes | the animal, donor or culture, as the depositor names it, or a reserved word |
| `injection` | no | integer, technical replicate within individual and sample |
| `fraction` | no | integer, or `not applicable` |
| `pool_size` | no | integer number of individuals pooled; 1 = one individual |
| `acquisition_batch` | no | a label (e.g. `OTF18-27xx`, `HCDOT_DDAwInclusion`), never a timestamp |
| `source_reference` | yes | as in `curated_sample_characteristics` |
| `evidence`, `confidence`, `curation_version` | as there | as there |

**`curated_design_factors`**, key (`run_id`, `factor`):

| column | required | what it is |
|---|---|---|
| `run_id` | yes | a core run |
| `factor` | yes | lower-case words from our list (`age group`, `disease`, `treatment`, `genotype`, `culture time`, `exercise`, `diet`, `surgery`, ...). The list grows, so it is not an enum |
| `level` | yes | the run's level, verbatim from the depositor where possible |
| `is_reference` | yes | boolean: the reference level of this factor in this dataset (our D71) |
| `term` | no | one CURIE (EFO, ChEBI, MONDO, PATO) |
| `source_reference` | yes | |
| `evidence`, `confidence`, `curation_version` | as above | |

**Checks we would want `build` to make:**
- within a dataset, each factor has at least one `is_reference = true` level and at least one other level;
- a run that appears in `curated_design_factors` also appears in `curated_run_design`.

Anything else is your call.

## DATAREPO-80 - protocol fields in `curated_sample_characteristics`: may `name` be an SDRF `comment[...]` header?

We want to deliver the protocol fields as dataset-wide values written once per sample:

  as carbamidomethyl);

The SDRF spec puts these under `comment[...]`, not `characteristics[...]`. Your column text says "the SDRF header form".
Does that include `comment[...]` headers, or do you want them elsewhere?
