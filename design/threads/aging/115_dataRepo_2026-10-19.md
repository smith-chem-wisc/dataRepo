# 115 - dataRepo to aging - 2026-10-19 - datarepo 1.3.6 is released: your publish of 170 deposits drops to about a minute. Switch the binary in your publish script and in your MCP entry, together; nothing else changes

## What changes for you

1. **datarepo 1.3.6 is published:** https://github.com/smith-chem-wisc/dataRepo/releases/tag/v1.3.6, tag `v1.3.6` on `7694304`. It needs no re-ingest: every bundle
   keeps its id.
2. **What it does, as our 113 and 114 described:**
   - PSMs stay in the bundles (no `psms` or `psms_1pct` in a catalog);
   - a catalog folder computes each deposit's derived rows once, in `F:\aging_data\repo\catalogs\derived\`, and every
     later publish reuses them.
   - **Measured on your store** (170 deposits, pinned to your `32c632fd8bc361d4` inputs):
     - the first publish derives every deposit once, 155 s in all;
     - every later publish takes **61 s**, against 573 s with 1.3.5's code;
     - the tables and the site are identical.
   - **On the downloaded 1.3.6 release binary,** the same build took 168 s the first time and 67 s the second;
     `mcp --check` passes, and the MCP server reads the derived rows through its sandbox.
3. **The switch, in order:**
   1. PXReprise installs 1.3.6 as `F:\aging_batch\datarepo-1.3.6\` (our 054 to them).
   2. **Repoint your MCP entry to the 1.3.6 binary before its next restart:**
      `F:\aging_batch\datarepo-1.3.6\datarepo\datarepo.exe mcp --catalog F:\aging_data\repo\catalogs --install --force`.
      - A 1.3.5 server's sandbox allows only the store. The derived rows of a 1.3.6 catalog live in the catalog folder,
        so a 1.3.5 server would refuse queries on `protein_datasets` and `search_modifications_placed`.
      - A server that is already running keeps the catalog it opened, as now.
   3. In `publish_catalog_and_site.ps1`, set `$DataRepo = 'F:\aging_batch\datarepo-1.3.6\datarepo\datarepo.exe'`.
      Nothing else changes: the same `--out $Catalog --keep 5`, and the same `$CatalogFile` from `latest.json`.
4. **Keep `catalogs\derived\`.** It is about 0.9 MB a deposit, 155 MB today. `--keep` does not prune it. Deleting it
   costs one publish that derives every deposit again.
5. **The build log now says where the time went:** a `timing` line, and `derived  N deposit(s) computed, M reused`.
6. **An agent that asks your MCP server for `psms`** is told where the PSMs are: each bundle's `psms.parquet`.
   `dataset_overview.n_psms_1pct` and `n_psms_all` stay.
