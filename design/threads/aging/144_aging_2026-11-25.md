# 144 - aging to dataRepo - 2026-11-25 - DEF-AGE-EFFECT v3: age rules scale with each species' lifespan; four new columns on age_effect and a read-time view per tenth of lifespan (DATAREPO-92)

## What changes for you

Our user ruled today (D232) that the age-effect definition must scale with the species' life ("Make an educated
decision and state it loudly and plainly. If it fails, we'll fix it."). Under v2's flat 10-year span, no rodent dataset
could ever give a row, and every dataset with ages in our catalog is a rodent.

New definitions in our repo:
- `aging:DEF-AGE-EFFECT v3` and `DEF-AGE-EFFECT-META v1.5`, in `design/DEF_AGE_EFFECT.md`;
- `aging:DEF-LIFE-COURSE v1`, in `design/DEF_LIFE_COURSE.md`, which is a lifespan and five life stages each for human,
  mouse and rat.

QuantProject fits the rows (our REQ-QP-17).

## DATAREPO-92 (asked)

**1. Four new columns on `age_effect`, and on `age_effect_refusals` where they apply:**

| column | type | meaning |
|---|---|---|
| `reference_lifespan_years` | double, NOT NULL on fitted rows | the species' lifespan from `DEF-LIFE-COURSE` (80 human, 2.4 mouse, 3.0 rat) |
| `life_course_version` | text, NOT NULL on fitted rows | `DEF-LIFE-COURSE` version, `v1` today |
| `stage_min`, `stage_max` | text | life stage of the youngest and oldest age fitted, one of `juvenile`, `young_adult`, `middle_age`, `old`, `very_old` |

**2. Three new status values** in `DEF-DIFF-STATUS`'s vocabulary:
- `below_support:min_eighth_lifespan_span`, which replaces `below_support:min_10_year_span`;
- `below_support:min_3_ages`, beside the existing `min_5_ages`, which stays for spline and breakpoint fits;
- `no_life_course`.

Please tell us which datarepo release reads them before any producer writes them. An unknown status value once failed
every ingest, not just one deposit's (PXReprise 333).

**3. A read-time view, `age_effects_by_lifespan`:** every `age_effect` column, plus
- `beta_per_tenth_lifespan = beta * reference_lifespan_years / 100`;
- `se`, `ci_low` and `ci_high` scaled by the same factor.

That is the change per tenth of the species' own life (8 years human, 2.9 months mouse, 3.6 months rat), the number to
set beside another species'. **The stored `beta` stays per chronological decade.** A revised lifespan changes the view,
never a stored value. That is §6.4's grain rule, which v3 keeps.

**Unchanged:** the meta key keeps `organism`, so species are never pooled.
