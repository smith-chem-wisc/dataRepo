## DATAREPO-P22 (answer): an artefact over artefacts is fine

`ptmqtl.pool_pairs` reads `site_pairs` artefacts by id and sha256, and its own id hashes them. A changed or added
dataset gives a new pooled artefact, never an edited one.

Pooling does **not** happen at build: `build` loads results and never computes them.

**One rule, the same as go's GO-D9:** all the `site_pairs` artefacts pooled into one `meta:<species>` must share one
definition version and one enrichment gate. Mixed inputs are refused.

## DATAREPO-P23 (answer): the enrichment gate is an operator `--input` now

The gate (which deposits enrich which PTM, D24) is an `--input` role, like go's `category_map`, until aging
records targets.
- **Supplied by the operator,** today aging's list.
- **Hashed into every artefact id,** so a changed gate gives new artefacts, and a result always names the list it
  was gated by.

Once DATAREPO-P20's manifest field exists (below), the engine reads the gate from the manifest instead, and the
`--input` role retires. We will say so before it changes.

## DATAREPO-P20 (answer, your 024): proposed; built when aging records targets

- **Where:** a per-dataset field in the instance manifest, filled by aging (the owner, AGING-P14). It lists the
  modifications a deposit's enrichment targets, by UNIMOD accession, with the runs it applies to when not every run
  is a capture.
  - `build` reads it, as it reads `dataset_annotations`. A correction needs no re-ingest; the catalog id moves.
  - `datasets.enrichment` stays as it is: it says how, and the new field says what.
- **A flag on `ptm_stoichiometry`:** yes. A catalog column, `on_enriched_deposit` (name to be settled), true where
  the row's modification is one its deposit enriches. It is derived at build, so it does not change the core schema
  and needs no re-ingest.
- **The flag goes where it cannot be skipped.** `datarepo_sql` warns on any query over `ptm_stoichiometry` whose rows
  include flagged ones (our D19: a tool must be chosen; an envelope field cannot be skipped).
- **Status:** proposed, not in `schema/datarepo.yaml`. We build it when aging answers AGING-P14.
