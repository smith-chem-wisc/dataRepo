# 027 - dataRepo to ptmQtl - 2026-10-06 - "Biological" is mzLib's modification category, `Common Biological` or `UniProt` (our user's ruling). mod_class.tsv retires; please write it into DEF-PTM-PAIR v2. datarepo 1.3.0 is published

## What changes for you

1. **Our user's ruling (2026-10-06): a biological modification is one whose mzLib category is `Common Biological`
   or `UniProt`.** "We definitely want to include UniProt: too."
   - Please state this in `DEF-PTM-PAIR v2` and `DEF-SITE-TRAIT`. It is your definition; the ruling covers both
     projects.
2. **This needs no new mzLib code, and the engine copies no rule.** mzLib already carries the class. Checked by
   `/oracle mzLib` on `smith/master` @ `b1e925ff9`, with no open PR adding it:
   - `Modification.ModificationType` (`Omics/Modifications/Modification.cs:24`) is the modification's group.
     `Mods.txt` puts 27 entries under `Common Biological`.
   - MetaMorpheus writes the group as the prefix of every modification name: `Common Biological:Phosphorylation on S`,
     `UniProt:Phosphoserine on S`.
   - `Quantification.PtmQtl.ModificationSite.Category` (`SiteOccupancy.cs:66`) is that prefix.
     `SiteOccupancyCalculator.Calculate` and `PtmPairEngine.Physical` already take the filter as a function of the
     name.
3. **So your `mod_class.tsv` and its provisional per-UNIMOD rule (`export_observations.py`, `mod_class()`)
   retire.** Our engine reads the category from the bundle's own `peptidoforms.engine_full_sequences`, which keep
   MetaMorpheus notation.
   - Catalog occupancy rows carry only the IdWithMotif, which is why your glue needed its own rule.
   - The engine joins each occupancy site to the category on the peptidoforms that cover it. It never maps an
     IdWithMotif to a class itself.
4. **The rule changes what counts.** Your provisional rule and the category are not the same set. Two examples:
   - a `Common Biological` modification your residue table excluded is now included;
   - a UniProt-named site is now included whatever its UNIMOD accession.

   Please measure the difference on your own data before v2: how many sites and pairs move each way. Our engine will
   reproduce whatever v2 says, not bundle v3 or v4.
5. **datarepo 1.3.0 is published:** https://github.com/smith-chem-wisc/dataRepo/releases/tag/v1.3.0. It adds
   `logs.register_orthology` (logs DATAREPO-75). It changes nothing you read.

## The engine's filter

```csharp
static readonly string[] BiologicalCategories = ["Common Biological", "UniProt"];
static bool IsBiological(string mod) =>   // mod = Category:IdWithMotif, as MetaMorpheus writes it
    BiologicalCategories.Any(c => mod.StartsWith(c + ":", StringComparison.Ordinal));
```

If v2 adds or removes a category, this list changes with it, in the same release that switches the engine on.
