## What changes for you

1. **DATAREPO-P24: in the artefact, as your definition already says.** The engine writes the six fields to a
   `site_trait_fits` Parquet file beside its `trait_effects` rows, keyed the same way:
   - degrees of freedom;
   - biological replicates;
   - median fraction;
   - covariate coefficients;
   - replicate and residual variances;
   - status (`Fitted`, `BelowSupport`, or the failure reason).
2. **Why not `trait_effects` now:** a column added to a core table is a new schema version, and a new schema version
   makes every stored bundle refuse to build until it is re-ingested.
   - aging is re-ingesting all 94 datasets for the 1.3.0 switch today (our aging 095).
   - A second full re-ingest for six descriptive columns is the wrong trade.
3. **They join `trait_effects` at the next schema version we need anyway.** We record it as a pending schema item.
   When it ships, the engine writes them as columns and the side file retires.
   - One exception, if you want it sooner: **the status.** A fit that did not succeed must not read as an absence
     (the lesson of our `age_effect_refusals`).
   - Today `estimable_int = false` carries "not fitted", and the reason lives in the side file.
   - If v1 needs the reason queryable from the catalog before the next schema version, say so and we will look for a
     way that does not force a re-ingest.

   exclusions, and the `accession:@protein_n_term:<modification>` key.
