### What each analysis needs

#### 1. Co-varying pairs within a dataset (needs to be fixed now; G29)

A co-varying pair is two sites whose occupancies move together across a dataset's runs. Anything that shifts many
sites at once in the same runs produces such pairs without shared biology. PXD035171 showed it: two acquisition
batches give 17,940 of 19,572 significant pairs.

| need | grain | why |
|---|---|---|
| acquisition date/time and run order | run | batch and drift are the first confounder; the raw file header carries it |
| instrument, LC method/gradient, acquisition batch label | run | as above, when the date alone does not separate batches |
| fraction and pool membership | run | fractions of one sample are not independent runs; they must be combined first |
| technical replicate / injection | run | two injections of one sample are one observation, not two |
| sample → individual | sample | repeated samples of one individual are not independent |
| **the design factors** (group, condition, treatment, time) | sample | if half the runs are disease and half control, every site that differs between groups correlates with every other: the design itself is a confounder, and pairs must be found within groups or after removing group means |

#### 2. PTM → trait (occupancy vs age, disease, treatment …)

| need | grain | why |
|---|---|---|
| the factor of interest, with its **reference level** (control, healthy, untreated, youngest) | sample | the comparison has to be defined, not guessed from file names |
| organism, strain/background, sex, age (value + unit + life stage) | sample | basic covariates; age is also a trait |
| organism part (tissue), cell type, cell line | sample | occupancy differs by tissue; it is a stratum, not noise |
| disease and stage; treatment agent, dose, duration; genotype (knockout, transgene) | sample | the traits themselves |
| timepoint and individual (repeated measures, pairing) | sample | paired and longitudinal designs need the individual as a random effect |
| pooled sample? how many individuals | sample | a pool is not a replicate |
| the comparison the authors made | dataset | the honest first test; and what was deliberately not compared |

#### 3. Pooling across datasets (global networks, the project's goal)

| need | grain | why |
|---|---|---|
| all of section 2, **as ontology terms** (NCBITaxon, UBERON tissue, CL cell type, MONDO/DOID disease, ChEBI treatment, EFO) | sample | datasets can only be pooled within the same stratum (same species, tissue, enrichment, healthy vs disease), and only terms make "same" checkable |
| a healthy/baseline flag | sample | networks should be built on baseline tissue first, disease second |

#### 4. PTM-specific: what the sample prep did to the modifications

Some modifications are made by the protocol, not the biology. Without these fields an artefact looks like a finding.

| need | grain | artefact it controls |
|---|---|---|
| digestion enzyme, time, temperature, pH | dataset or sample | Asn/Gln deamidation rises with long, warm, basic digestion |
| lysis/denaturant (urea?), alkylation agent | dataset | carbamylation from urea; over-alkylation |
| storage time, freeze–thaw, sample age before processing | sample | oxidation and deamidation accumulate in storage, and in an aging study they can track age |
| enrichment target and method per run (have) | run | enrichment, not abundance |
| phosphatase/deacetylase inhibitors | dataset | loss of labile modifications |
| modifications searched (have) | dataset | a modification not searched is absent, not zero |

#### 5. Interpretation

| need | grain | source |
|---|---|---|
| GO terms, compartments | protein | go project via dataRepo (mzLib #1353 merged, not released) |
| protein half-life / long-lived proteins | protein | a curated list or published turnover data |
| gene mapping (have) | protein | `protein_genes` |

### Minimum to unblock, in order

1. Run acquisition date/time and instrument for every run, plus fraction and injection (G29, and correctness for fractionated deposits).
2. For each dataset: the design factors and their reference levels, per sample, and the individual.
3. Tissue, cell type, disease, treatment, sex and age as ontology terms.
4. Protocol fields for deamidation and oxidation (digestion, storage).
5. GO in the catalog.

Until 1–2 exist for a dataset, ptmQtl results on it are descriptive only and say so.
