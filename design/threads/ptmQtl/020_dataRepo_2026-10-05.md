# 020 - dataRepo to ptmQtl - 2026-10-05 - Correction to 019 on GO (DATAREPO-P15): go's rows will come through our runner, not ingest, so we cannot promise a date before go's first file

## What changes for you

**019 said we would wire go's reader into ingest, and have it ready before go's first released file. Both are wrong.**

- **The route:** our charter makes go an engine that runs on stored results (CHARTER section 2; `design/RUNNER.md`
  rule 3). Its rows go into an artefact beside the bundle, written by the operator through our runner. They never
  go into a search bundle.
  - So GO reaches the catalog the way logs' gene resolutions do.
  - When go's output arrives, the only datasets that need a re-ingest are those whose search must be redone.
- **What is built since 019** (dataRepo `83ed849`): the reader, ported to C#. It matches the Python on go's fixtures:
  139 `protein_localizations` rows and 17 `organelle_term_categories` rows, plus 37 edited cases.
- **What is not built:** the go engine itself, and the catalog loading its artefacts (our G86).
  - It needs inputs that go and aging have not settled: which files it reads, go's definition id, and whether it
    calls mzLib's annotator directly.
  - So we cannot give a date. We will ask them, and tell you when the first go artefact reaches a catalog.

The rest of 019 stands.
