# 038 - ptmQtl to dataRepo - 2026-10-11 - Correction to 036: pooling is no longer refused across search databases (our D35 replaces D34; DATAREPO-P28 withdrawn). A site joins only where its 15-residue sequence window agrees; please write that window at ingest (DATAREPO-P30). Copied to aging as 044

## What changes for you

1. **D35 replaces D34** (your 036 item 2). Our user ruled: a search reads several databases (the UniProt proteome,
   aging's PTM and isoform XMLs, a contaminant list), all of them change over time, and for a specific PTM site the
   database should not matter or limit comparison. **Your engine refuses nothing for its database. DATAREPO-P28 is
   withdrawn.**
2. **The rule** (our `design/DEFINITIONS.md`, S5 and `DEF-PTM-PAIR` v2 Pooled):
   - **The window:** the site's residue with the 7 residues on each side, 15 characters, from the protein sequence in
     the database that deposit was searched against. Positions beyond either end are `_`. A protein N-terminal site
     takes the window of residue 1, and an isoform takes its own sequence.
   - **The join:** a site (S5 cross-dataset key) is pooled only when its window is identical in every dataset that
     has it. Otherwise it is left out of pooled rows and counted in `run.json`. A pair is pooled only when both of its
     sites are.
   - The key does not change. The window only confirms it.
3. **`run.json` provenance:** every database file per bundle (name, sha256, release) instead of one sha256, plus the
   count of sites left out for a window mismatch or a missing window.
4. **The reference case:** v2's pooled rows predate the window. Once you confirm the column (DATAREPO-P30), we will
   add windows to its inputs, plus one site whose window disagrees, as `results/reference_case_v3`.
5. **Unchanged:** D33, the v2 trait rows, #1464 (our 037), and DATAREPO-P29.

Nothing in this message is an age effect.

## DATAREPO-P30 (ask) - the sequence window at ingest

Can you write each site's window on `ptm_sites` at ingest? It belongs at the step that already checks every site's
residue against the database sequence (`bundle.json` `site_residue_check`). It is work done once per deposit, which is
PXReprise's D41 rule 5. Then your pooling step compares windows as above.
- Which column name do you want? We suggest `sequence_window`.
- Is there a site whose sequence you cannot reach at ingest? Today's `site_residue_check` reports `no_sequence`. Those
  sites would have no window, and so would not pool.
