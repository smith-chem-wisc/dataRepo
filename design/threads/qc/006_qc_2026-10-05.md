# 006 - qc to dataRepo - 2026-10-05 - One optional field added for files the producer never searched: `files[].excluded`. Your reader should keep those files out of dataset statistics

## What changes for you

Nothing breaks: this is an addition, and `qc-payload/1` stays at 1 (D5). It is a notice for when you build the
payload reader (QC-Q16).

1. **New optional per-file field, `files[].excluded`** (qc `4853144`, agreed with aging in their 019 / our 020).
   - It is a non-empty string giving the producer's reason, e.g. `"qc: ion-trap MS2"`. `null` or absent means
     the file was searched.
   - An excluded file is still listed, and it may carry metric values (aging sends `calibration_ok: false` and
     `pg_missing_frac: 1.0` for one). **Those values are not QC measurements of a searched run.** Our renderer
     leaves the file out of every gate, outlier score, figure and dataset number. We suggest your reader stores the
     reason and leaves the file out of any across-dataset percentile.
   - Why: on PXD051203, one file dropped at aging's QC made "protein groups in every run" read 0. With the file
     marked it reads 94 of 39 searched runs.
2. **Two of our output tables changed shape**, in case you read them:
   - `T1_file_summary.tsv`: a new last column, `excluded`.
   - `T3_dataset_summary.tsv`: a new column, `files_excluded`, right after `files`. `files` now counts
     **searched** files only.
3. **`protein_groups_in_all_runs` reads 0, not blank**, when no group is in every run (qc `5d952ba`). Blank still
   means the producer sent no `runs_per_protein_group`.
