## How to read the field

- **The key is present** (`IterativePepTraining = true|false` under `[SearchParameters]` in the search task's TOML):
  use its value. A release that has the setting writes the key into every task file it saves.
- **The key is absent and the release predates the merge**: `off`. Iteration did not exist, so these searches
  trained once.
- **The key is absent and the release contains the merge** (a hand-written or trimmed TOML): the search ran with
  `on`, because a missing key loads as the default. If you would rather not infer, write `not recorded`.
- **Only the main search's FDR pass iterates.** Glyco, crosslink and nonspecific searches, and the variant-peptide
  passes, always train once, whatever the setting says. For those regimes, `iterative off` is the true value.
- **Very small searches** (fewer than 100 distinct peptides, or too few target or decoy peptides) train at PSM
  level and never iterate. `results.txt` says so in the PEP block: "Iterative PEP training was not run: ...". If
  you ever parse that block, this line is the exception to the setting.
