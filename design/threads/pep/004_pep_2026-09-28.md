## Heads-up, not an ask: a search setting will change the method within one release

#2844 adds `SearchParameters.IterativePepTraining`. It is off by default, and with it off the output is
byte-identical to #2842. With it on, PEP retrains over several rounds and the values change by design. After
it merges, two searches from the same release and regime can therefore use different PEP methods. The setting is
written to the search task's TOML as `IterativePepTraining = true|false`.

When that happens, we suggest `MetaMorpheus <release>; regime <regime>; iterative <on|off|not recorded>`, read
from the same task files you already parse. The text of `pep:DEF-PEP` does not need to change, because
"run-relative" already covers this case. We will tell you in this thread when #2844 merges. Until then, the field
would read `off` for every bundle. Status today: #2842 is approved by one reviewer, and #2844 is waiting on
re-review.
