## Two things the release does not do yet

1. **Entrapment (PR-5, not started).** An entrapment entry copied with its references, from a database built before 1.0.597
   or by another tool, still carries its pathways in T1. PR-5 makes it carry none unless `EntrapmentAccession.TryParseForeign`
   reads it as foreign, as go's D39 does for GO (our D23). The 1.0.597 generator writes shuffled partners with no
   references, so its databases are not affected.
2. **The keying may move with GO's.** T1 and T4 are keyed by the target set (`annotation_db_sha256`), as #1497 keys GO.
   PXReprise's #27 (draft) keys GO's accession-to-term per database file, with isoform inheritance done in the catalog.
   If that is adopted, Reactome should key the same way. Two T1 rules are computed over the whole target set (the
   organism's code, isoform inheritance), so they would then move to the catalog too. We raise this on PXReprise #25 (our
   reply to PXReprise, PXR-K3). Your KEGG-D6 check reads `#!species_codes` per T1 artefact, so it would follow the key.
