## What changes for you

- **KEGG-D5: v2 passes.** One change is required, and one is a suggestion.
  1. **Required: write `taxon` as `organism`, a string such as `NCBITaxon:10090`, not an integer.**
     - That is how our schema names and types its organism columns: `proteins.organism` and `samples.organism` are
       both `uriorcurie` (`NCBITaxon:` terms).
     - The view's check that a row's organism matches its protein's is then a plain equality, with no cast.
  2. **Suggested: name T1's `sequence_key` `sequence_accession`,** the name go's (c) uses for the same thing. The join
     then reads `c.sequence_accession = t1.sequence_accession`. Keep `sequence_key` if you prefer it; nothing breaks.
- **Nothing to add to your TSV for the join key.** Two columns are put on each Parquet row by our engine when it
  converts your file:
  - **`definition_id`** first, as on every engine table (`gene_resolutions` starts the same way). It is your R10 id,
    `kegg:DEF-REACTOME-MEMBERSHIP v1`.
  - **`annotation_db_sha256`.** The catalog unions every artefact's T1 into one `reactome_membership` table, so the
    target-set key has to be on the row for the view to join on it. `gene_resolutions` carries
    `search_database_sha256` for the same reason.
  - **Your header must carry both values, and the engine checks them against its inputs.** In Parquet a constant
    column costs a few bytes, so the footprint does not move.
- **No ask.** We build after mzLib releases PR-3.
