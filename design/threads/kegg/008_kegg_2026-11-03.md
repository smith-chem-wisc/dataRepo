# 008 - kegg to dataRepo - 2026-11-03 - Two amendments to kegg:DEF-REACTOME-MEMBERSHIP v1: a member with no pathway never reads `annotated` (your view changes), and taxon-less entries are one organism, `unknown`. Plus T1's header shape

## What changes for you

- **Your member view changes (D20).** Until now the rule was: a member that takes no pathway reads the T1 status of its
  `annotated_as` entry. **When that entry reads `annotated`, the member now reads `no_reference`.**
  - **When it happens:** the entry's references are all scoped to other isoforms. Example: entry P77777's only
    Reactome reference is scoped to `P77777-2`. Member `P77777-3` takes whole-entry rows on `annotated_as` (none) and
    isoform rows on `sequence_accession = 'P77777-3'` (none). The old rule gave it `annotated` with no pathway.
  - **Why:** `annotated` must always mean at least one pathway.
  - **How rare:** 610 of 47,539 human Reactome rows are isoform-scoped (`results/xml_survey`). Entries whose references
    are all isoform-scoped are a subset of those.
  - **In SQL terms:** `CASE WHEN n_pathways > 0 THEN 'annotated' WHEN c.resolution = 'no_entry' THEN 'no_entry'
    WHEN entry_status = 'annotated' THEN 'no_reference' ELSE entry_status END`.
  - mzLib's tables do not change for this.
- **T1's `organism` can be empty (D19).** An entry with no NCBI taxon has an empty `organism`. This is typically a
  FASTA entry without `OX=`, such as a contaminant list. All such entries are treated as one organism for the species
  rule, named `unknown` in the header and in `run.json`. With no Reactome reference among them, which is the normal
  case for FASTA, they read `species_not_covered`. The alternative was to refuse the database, which would break every
  search that adds a contaminant FASTA.
- **The definition stays v1.** It is still a draft, and no artefact has been built from it. The text is
  `E:\CodeReview\kegg\design\DEFINITIONS.md` (rule 2, and "Per member").

## T1's header, as PR-4 writes it

mzLib's strict reader refuses a repeated or undeclared header key, so each map is packed into one line:

```
#!reactome_membership_format 1
#!mzlib_version ...
#!mzlib_release ...
#!definition kegg:DEF-REACTOME-MEMBERSHIP v1
#!annotation_db_sha256 ...
#!species_codes NCBITaxon:10090=MMU;NCBITaxon:9606=HSA
#!unvalidated_organisms NCBITaxon:9031=12;unknown=2
#!dropped_foreign_references 8
accession	organism	pathway_id	molecule	sequence_accession	inherited	status
```

- `species_codes`, `unvalidated_organisms` and `dropped_foreign_references` are written only when they are not empty
  or zero.
- Entries are `;`-separated, and each is `organism=value`, in ordinal order of organism.
- T4 (`kegg_gene_links_format 1`) carries `annotation_db_sha256`, and its columns are `accession` and `kegg_gene_id`.
