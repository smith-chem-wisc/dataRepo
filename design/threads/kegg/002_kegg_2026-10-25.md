### 2. Tables (DATAREPO-K1)

All tables are Parquet only. All are species-agnostic: species comes from the data (the id prefix and the XML's
taxon), never from a list, so a fourth species is one more T1 and no schema change.

**T1 `reactome_membership`**
- **One artefact per** (search database sha256, definition version, mzLib release).
- **It reads no Reactome file,** so a new Reactome release leaves every T1 untouched.

| column | type | meaning |
|---|---|---|
| `accession` | string | the entry's accession, exactly as the search database writes it (R2) |
| `pathway_id` | string, null | the Reactome stable id, verbatim (`R-MMU-109582`). Null only on a status-only row |
| `molecule` | string, null | `<molecule id>`, verbatim (`O00159-3`). Null means the reference covers the whole entry |
| `molecule_is_displayed` | bool, null | the molecule is the entry's displayed (canonical) isoform, read from the same XML |
| `status` | enum | see below |

**Statuses:**
- `annotated`;
- `no_reference`: UniProt lists none for this entry, which is **not** the same as "in no pathway";
- `species_not_covered`: no entry of this taxon in the database has any reference;
- `shuffled_entrapment`: a shuffled entrapment copy, which never carries a pathway (go's D39 rule, decided by
  `EntrapmentAccession` from mzLib#1271). A foreign-proteome entrapment entry keeps its own references.

`contaminant`, decoy and `no_entry` come from (c) and the catalog, never from T1.

**Grain:**
- one row per reference;
- one row per entry with none.

**Size:** 56,790 / 44,407 / 39,593 rows, about 260 / 200 / 175 KB.

**Not on rows:** names, releases, ancestors and hashes are not stored on T1 rows. They go in `run.json`, together with
the count per status and the taxon → species-code pairs seen.

**T2 `reactome_pathways` and T3 `reactome_hierarchy`**
- **One artefact per Reactome release,** keyed by the sha256 of `ReactomePathways.txt` and of
  `ReactomePathwaysRelation.txt`.
- **One release per catalog** (R9).
- **They hold all 16 species,** so there is no species list. For three species only, they would be 0.45 MB smaller.

| table | columns | rows | size |
|---|---|---:|---:|
| T2 | `pathway_id`, `name`, `species_name`, `human_equivalent_id` | 23,603 | ~460 KB |
| T3 | `parent_id`, `child_id` | 23,717 | ~120 KB |

What `human_equivalent_id` holds:
- for a human pathway, its own id;
- otherwise `R-HSA-<same number>`, when that exists **and** has the same name;
- otherwise null.

In Reactome it is exact for every inferred species: all 1,845 mouse and 1,833 rat pathways match.

**T4 `kegg_gene_links`**
- **One artefact per search database.**
- **Columns:** `accession`, `kegg_gene_id`.
- **Rows:** 19,405 / 18,644 / 13,526, about 0.1–0.3 MB each.
- **It is a link list, not an annotation.** See KEGG-D1 on whether R5's status rows apply.

**Explicitly not stored:**
- ancestors on rows (2.85× the rows);
- names on rows, or UniProt's copy of the names (its 10 real differences from Reactome's are spelling only);
- a top-level area per row;
- anything per deposit or per group;
- Reactome's `UniProt2Reactome*` files;
- gene-set sizes, a curated "level", or enrichment results;
- any KEGG content beyond the ids.

### 3. Views (dataRepo's; zero bytes)

**`protein_reactome`:** `proteins` → `dataset_databases` (role target) → (c) → T1 → T2. It applies three rules.

1. **The isoform rule.**
   - A row with null `molecule` applies to every member that (c) maps to the entry, through `annotated_as`.
   - A row with a molecule applies only to the member whose sequence it is:
     `c.sequence_accession = CASE WHEN molecule_is_displayed THEN accession ELSE molecule END`.
     This is an equality join, and it needs (c)'s `sequence_accession` (KEGG-G1 to go, thread 003).
2. **Keep only ids whose prefix matches the database's species.** One human entry, P47985, carries 8 other species'
   ids.
3. **An id absent from the pinned release reads as `not_in_release`,** with no name and no ancestors. Today there is
   1 such id in mouse and 1 in rat.

**Group level:** the union over members, with `members_in_pathway` / `members`. Never the "first" member: MetaMorpheus
sorts members alphabetically.

**`reactome_ancestors`:** a recursive view over T3, or a closure materialised once per release (77,465 rows, about
0.33 MB), as go does for GO. dataRepo's choice (KEGG-D2).

**`protein_reactome_area`:** the top-level areas per group. There are 28–29 per species, and a group may sit under
several.

**`reactome_equivalence`:** T2 grouped by `human_equivalent_id`. Two caveats go in the definition:
- **Disease is never inferred to mouse or rat.** It is 27% of human pathways and should be flagged, and excluded from
  cross-species comparison.
- **Mouse and rat membership is a hypothesis.** It is inferred by Reactome through orthology, not observed. Outside
  Disease, about 19% of human memberships are missing on the same-symbol mouse gene.
