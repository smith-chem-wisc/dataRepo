## The definition draft (`design/DEFINITIONS.md`, 2026-10-25)

### `kegg:DEF-REACTOME-MEMBERSHIP v1`: DRAFT (2026-10-25). It ships with mzLib PR-3, together with a fixture

#### What membership means

**A protein is a member of a Reactome pathway when the searched UniProt XML lists that pathway on the protein's
entry.**
- That is an entry-level `<dbReference type="Reactome">`.
- UniProt takes these from Reactome's lowest-level mapping: release 96 for UniProt 2026_03, measured, not documented.
- Membership is UniProt's statement, recorded verbatim. No Reactome file is read to decide it.
- **Ancestor pathways are not stated.** They are derived from the pinned Reactome release's closure.

**Mouse and rat (and every non-human) membership is Reactome's inference from human through orthology.** It is not
evidence observed in that species.

#### Inputs and identity

**Input:** the target proteins of one search: every target file the search loaded, loaded together. This is the same
protein list that go's member resolver (c) is built from. Decoys are ignored.

**Artefact key:** (`annotation_db_sha256`, definition version).
- `annotation_db_sha256` is dataRepo's target-set hash, the same as GO's (a).
  - For one file it is that file's sha256.
  - For several files it is the hash of `annotation-databases/1\n` followed by the sorted sha256s, one per line.
- The mzLib release that wrote the artefact is **provenance, not identity.** It goes in the header and `run.json`.

#### Per-entry rules (table T1), in order

1. **Read only entry-level `dbReference`s whose `Type` is exactly `Reactome`.**
2. **Species.**
   - **An entry's taxon** is its own `<organism>` NCBI taxon.
   - **A taxon's Reactome code** is the id prefix that most of that taxon's Reactome references in the loaded list
     carry: HSA for 9606, MMU for 10090, RNO for 10116.
   - **A reference whose prefix differs from its entry's taxon's code is dropped** and counted in `run.json`. Human
     P47985 carries 8 such references.
   - `run.json` lists the taxon → code pairs it found.
3. **Isoform scope.**
   - A reference without `<molecule>` covers the whole entry. Its `sequence_key` is null.
   - A reference with `<molecule>` covers that isoform only, and its `sequence_key` is:
     - `MemberResolver.SequenceAccessionOf(accession)` when the molecule is the entry's **displayed** isoform (the
       `<isoform>` whose `<sequence type="displayed"/>`);
     - otherwise the molecule, verbatim.
4. **Inheritance (go's D37).**
   - **When it applies:** an entry whose accession is a UniProt isoform (`ProteinAccession.Parse` gives an isoform),
     which has **no** Reactome reference of its own, and whose entry is in the loaded list with at least one
     whole-entry row.
   - **What it gets:** the entry's whole-entry rows, flagged `inherited`.
   - **Molecule rows are never copied.** They reach the isoform's members through `sequence_key`.
   - **An isoform with references of its own** keeps only those.
5. **An accession present more than once in the loaded list** has its rows unioned, as in GO's (a).
6. **Every entry gets at least one row.**

#### Statuses

**Per entry (T1):**

| status | meaning |
|---|---|
| `annotated` | at least one row carries a pathway, its own or inherited |
| `no_reference` | UniProt lists no Reactome reference for this entry, and the entry inherits none, while its taxon is covered. This means "UniProt lists none", **not** "in no pathway" |
| `species_not_covered` | no entry of this taxon in the loaded list carries any Reactome reference |
| `shuffled_entrapment` | a shuffled entrapment copy. It never carries a pathway, even if the generator copied its target's references. Added by PR-3b, which needs `EntrapmentAccession` from mzLib#1271. Until then the status does not occur. A foreign-proteome entrapment entry is annotated by its own references under rule 2 |

**Invariant:** a row that carries a pathway reads `annotated`.

**Per member (the catalog view, through (c)):** a member takes two kinds of row.
- **Whole-entry rows:** T1 rows where `T1.accession = c.annotated_as` and `sequence_key` is null.
- **Isoform rows:** T1 rows where `T1.sequence_key = c.sequence_accession`.

Take both with `DISTINCT`, because an entry and its applied variants can carry the same isoform row.

Its status is the first that applies:
1. `annotated`, if it has any row.
2. `contaminant`, if the catalog marks the member as from the contaminant panel. A contaminant that is also a target
   entry is annotated from its target entry (GO-D5).
3. `shuffled_entrapment`.
4. `no_entry`, if (c) says the search database does not hold it.
5. `species_not_covered`.
6. `no_reference`.

**A group's status** is its highest member status in this precedence:
`annotated > contaminant > shuffled_entrapment > no_entry > species_not_covered > no_reference`.

#### Group-level counts

These are computed in the view, per group and pathway.
- **Eligible members:** `resolution ≠ no_entry`, not a contaminant, not entrapment.
- **`members`:** the number of eligible members.
- **`members_in_pathway`:** the eligible members carrying the pathway.
- **The group's pathways:** the union over eligible members.
- **A group-level count is never written onto a per-member row** (go's D33).
- **No member is "first" or "leading."** MetaMorpheus sorts members alphabetically.
- **Entrapment members are labelled, never dropped.** They stay out of both an enrichment hit list and its background
  (go's D3, D32).

#### Ancestors and release drift

- **Ancestors:** pathway P is under A when (P, A) is in the pinned release's closure. The closure includes P itself.
- **Release drift:** an id absent from the pinned release reads `not_in_release`, with no name and no ancestors. The
  catalog build counts these per target set.
- **The pinned release** follows the search databases' UniProt release. There is one per catalog (PXReprise rule 5,
  KEGG-P2).

#### Cross-species

- **`human_equivalent_id`:**
  - for an `R-HSA` id, the id itself;
  - otherwise `R-HSA-<same number>`, when that id exists in the pinned release **with the identical name**;
  - otherwise null.
- **Disease** (`R-HSA-1643685` and everything under it) is never inferred to other species. The view flags it by
  ancestry, and it is excluded from cross-species comparison.

#### Edge cases decided

- **A member written as the displayed isoform's own id** (`X-1` when `-1` is displayed) does not occur in UniProt's
  files. If it does occur, its `sequence_accession` (`X-1`) matches no displayed key (`X`), so it takes whole-entry
  rows only. It is not repaired.

#### KEGG gene links (T4, in the same artefact as T1)

- **What it holds:** every entry-level `KEGG` dbReference id, verbatim, as a link to `https://www.kegg.jp/entry/<id>`.
- **No status rows.** For a target set that has the artefact, "no row" means UniProt lists no KEGG id.
- **No KEGG content beyond the id** is stored, and nothing calls KEGG (D2).
- **`run.json` carries UniProt's CC BY 4.0 attribution verbatim.**
