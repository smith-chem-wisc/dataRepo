- **What happened:** `label-free-dda@13`, mouse, searched 01:06 to 09:59 UTC 11-05. The ingest with 1.4.1 failed at
  10:09 UTC (rc 1, `status: error`):

  ```
  System.OutOfMemoryException: Insufficient memory to continue the execution of the program.
     at System.String.CreateStringFromEncoding(Byte* bytes, Int32 byteLength, Encoding encoding)
     at System.Text.UTF8Encoding.GetString(Byte[] bytes, Int32 index, Int32 count)
     at DataRepo.Ingest.PyText.DecodeUtf8Sig(Byte[] bytes, Boolean strict) in ...\Readers.cs:line 853
     at DataRepo.Ingest.Readers.ReadTsv(String path, ReaderLog log, String note, IngestRules rules) in ...\Readers.cs:line 389
  ```

  Full output: `F:\aging_data\batch\outputs\PXD025315_ingest_20261105T100928Z.log`.
- **Why:** `ReadTsv` calls `File.ReadAllBytes` and decodes the whole file into one string. PXD025315's
  `AllQuantifiedPeaks.tsv` is 1,491,686,516 bytes of ASCII. A .NET string holds at most 1,073,741,791 characters, so
  the decode throws `OutOfMemoryException` whatever memory is free. This machine has 512 GB; 419 GB were free this
  morning.
- **The same code is on `feat/1.4.2`** (3447228, `Readers.cs` line 389). Every table read through `ReadTsv` has the
  limit: `Quant.cs` lines 97, 129, 210 and 233, `Isobaric.cs` 97 and 207, and `SampleColumns.cs` 238. Only the peak
  table is near it today.
- **PXD025315 is the first to cross.** The largest `AllQuantifiedPeaks.tsv` files in our run root are:

  | deposit | MB |
  |---|---|
  | PXD025315 | 1,423 |
  | PXD034590 | 824 |
  | PXD018999 | 745 |
  | PXD019279 | 743 |
  | PXD025240 | 687 |

  Large label-free deposits will keep crossing it.
- **PXR-R48:** can `ReadTsv` read line by line, for example `File.ReadLines` or a `StreamReader` with strict UTF-8 and
  the BOM stripped? Can `PeakQuality` take the rows as a stream, so a peak table is never held whole? And which
  release would carry it?
- **What we do meanwhile:** nothing to the search. Its `04_search` stays on disk as it is, `AllPeptides.psmtsv`
  included (your 083). The batch retries a failed ingest at every driver start, so PXD025315 is delivered at the first
