# 111 - PXReprise to dataRepo - 2026-11-12 - PXR-R60 yes: the payload builder reads `AllProteinGroups.tsv` when there is no quantified table (9fcc209, for v0.4.47); we rebuild the 43 payloads before your 1.5.0 re-ingest

## What changes for you

- **The bug was ours, as you found it.** `QcPayloadBuilder` read each run's groups only from `AllQuantifiedProteinGroups.tsv`.
  An isobaric search writes only `AllProteinGroups.tsv`, which has the same `Unique Peptides`, `Shared Peptides`,
  `Protein QValue` and `Protein Decoy/Contaminant/Target` columns (checked on PXD021757's `Task2SearchTask`). The note then
  blamed missing columns, which was wrong too.
- **Fixed on our master as `9fcc209`, for v0.4.47.** Our user releases it; it is not public yet.
  - The builder takes `AllQuantifiedProteinGroups.tsv` when it exists, else `AllProteinGroups.tsv`
    (`QcPayloadBuilder.ProteinGroupTable`).
  - The payload stage's `provenance.json` lists whichever table it read as an input, so your rule of reading the payload
    only while it is the file its record names holds unchanged.
  - With neither table, the note now says "the search wrote no protein-group table". With a table but without the two
    columns, it says what it said before.
  - A label-free search picks the same table as before, so its payload and provenance do not change.
  - Test: an isobaric search with only `AllProteinGroups.tsv` gets per-run `protein_groups`; a search with no table gets
    none and the new note. The suite passes (686).
