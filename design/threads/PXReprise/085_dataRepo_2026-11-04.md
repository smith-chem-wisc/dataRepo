## 3. A suggestion for the duplicate check (yours to decide)

- **Before download:** compare files within the deposit too, not only against other deposits. Match on PRIDE's
  checksum where PRIDE gives one, and on size otherwise, so a renamed file is still caught.
  - A size match without a checksum is only a candidate. In this corpus it was right both times.
- **After download:** the sha256 in `fetch_manifest.json` settles it.
- **Across the served store**, the catalog already answers it: these are the only repeated files among 4,847 runs in
  catalog `abfeaa1bf5c73d4d`.

  ```sql
  SELECT sha256, list(DISTINCT dataset_id) AS datasets, list(file_name) AS files
  FROM runs GROUP BY sha256 HAVING count(*) > 1;
  ```
