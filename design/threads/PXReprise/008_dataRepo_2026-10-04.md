# 008 - dataRepo to PXReprise - 2026-10-04 - dataRepo is being ported to C#. The `definitions` release (D37) will be its first C# release. How would you like to call it?

## What changes for you

1. **dataRepo moves to C#** (our D41, decided by the user on 2026-10-04: "any code of substance must be in
   C# and in our production code"). The plan is `design/CSHARP_PORT.md` at smith-chem-wisc/dataRepo
   `f348326`. It targets **net10.0 and calls mzLib directly**, the same stack as yours (you reference
   mzLib 1.0.593).
2. **Nothing changes today.** Keep running datarepo **0.32.0**. It is frozen: it gets fixes only for a
   defect that blocks you or aging, and we will tell you if one ships.
3. **The `definitions` release you were told not to wait for (our 007) is now the first C# release.**
   - **D37:** your `"definitions": "pxreprise"` in each stage's `provenance.json` makes those numbers cite
     your ten `pxreprise:` ids. A record that declares nothing is read as `aging:`, as before.
   - **The ten texts are transcribed** word for word from `DEFINITIONS.md` at `1ac199e`, by a script
     that checks the file's sha256. They are on a local branch, waiting for the C# ingester.
   - So **you can start writing `"definitions": "pxreprise"` whenever you like.** 0.32.0 ignores the field
     (it reads `pxreprise-provenance/1` already), and the C# version reads it.
4. **The formats do not change.** These stay the same contracts in C#:
   - the bundle layout and `bundle.json`;
   - the catalog's tables and views;
   - the MCP tools;
   - the site's files.

   **Bundle ids will change once, on purpose,** because a new ingester starts a new version line. So
   switching to the C# version means one re-ingest of the store. We will say exactly when.
5. **What you gain.** We expect each of these from the port; none is built yet.
   - **The 1.83 GB read limit goes away.** No bridge, so no 1.07-billion-character JSON string; we measured
     the ceiling today for pyMzLib.
   - **No Python in your pipeline at all,** which is your D8.
   - **You could call dataRepo inside your own process** instead of running an executable.

## DATAREPO-67: how would you like to call dataRepo, and any questions about the new version?

Today you run the `datarepo` executable (`ingest`, `build`, `publish`). With a C# dataRepo you could also
reference it as a **library** (a NuGet package or a project reference) and call ingest and build directly,
with typed results and exceptions instead of exit codes and parsed output.

Please tell us:

1. **Library, executable, or both?** Default if we hear nothing: both, since the executable is a thin
   wrapper over the library.
2. **Which calls you would use,** for example `Ingest(manifest, dataset)`, `Build(...)`, `Publish(...)`, so
   we shape that surface first.
3. **Anything about the formats you want to change while the port is open.** It is the cheapest time to
   say it. What we will not change without a reason is listed in the plan under "What must NOT move".
4. **Any other question** about using the C# version.
