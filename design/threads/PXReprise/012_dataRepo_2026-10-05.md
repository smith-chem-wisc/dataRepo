## DATAREPO-72 (ask): per-run start time and instrument in the spectra QC report

**Why.**
- ptmQtl's batch correction (their G29, thread 017) needs each run's acquisition time first. Their PXD035171 showed
  two acquisition batches making 17,940 of 19,572 significant pairs.
- **No stored run has a time today:** 0 of 1,914 runs in aging's catalog `0a97df7856bb8e4e`.
- **We cannot fill it, by design.** We never re-read spectra, and the run folder keeps no spectra after the search:
  `02_fetch/spectra` is emptied, and no calibrated mzML is kept.
- `qc_report.json` gives per run only these: `pass`, `scans`, `ms2`, the analyzer and dissociation, `run_minutes`
  and `charge_states` (checked on PXD077298).
- So your QC stage, which reads every raw file, is the last place these facts exist.

**What we ask.** Three per-run fields in `qc_report.json`, beside `run_minutes`:

| field | value |
|---|---|
| `start_time` | the file's acquisition start, exactly as the reader reports it |
| `instrument_model` | as the reader reports it |
| `instrument_serial` | if the reader exposes it |

A key that is missing or null means "not read". Never write an empty string.

**One trap.**
- A Thermo RAW start time is the instrument's LOCAL time, though labelled UTC (aging 055, mzLib #1349). An mzML's
  is in the converting machine's zone.
- Please write the value as read, and say in your provenance which reader and format it came from. Do not convert
  it.
- We will store it as written, beside the source format, so nobody compares times across deposits as if both were
  UTC.

**What we do when it appears.**
- Ingest `start_time` into `runs.acquisition_datetime` and `instrument_model` into `runs.instrument_model`. Both
  columns exist already; today the model comes only from the SDRF, one value per deposit.
- The serial would need a new column. We add it only once you write it.
- This is one C# ingester change, with its own version bump.

**For the 91 deposits already searched,** the raw files are gone, so their times need a re-fetch. That is aging's
call (ptmQtl asked them, aging 026 AGING-P12); we only flag that no ingest change can stand in for it.
