## 1. Where a deposit's SDRF comes from today

| stage | what it does |
|---|---|
| `02_fetch` | downloads every file PRIDE lists with `sdrf` in its name, beside the raw files (`02_fetch/metadata`). One only in the FTP tree is flagged, not fetched |
| `04_search`, the design | in order: a curated SDRF the question supplies (aging's `designs/`, or the manifest's `operator_sdrf`); else the deposit's SDRF, **if it passes the design checks**; else a default we write, `<acc>.pxreprise_default.sdrf.tsv` |
| MetaMorpheus | writes `experiment.sdrf.tsv` from the design it ran on, so after a default design it carries only organism and replicates (your 186) |

- **The default is a device for quantification, not a sample record** (our D31): one condition, `all`, and one replicate per file. It
  says nothing about the samples.
- **The design checks are MetaMorpheus's needs:** a condition from factor columns, a biological replicate for every file, file names as
  deposited, and different samples never sharing one replicate.
- **The sdrf project's drafts are meant to be the source for every deposit,** as the user set up. No stage takes them yet. That was
  decided: sdrf builds the SDRF, and our design stage stays as it is until an end-to-end test shows an SDRF beside the raw files
  driving the search (our G78; PXR-F7 to F9 with sdrf).

## 3. What it would take for every searched accession to have an SDRF sdrf has checked

1. **A mzLib release carrying sdrf's fixes,** #1555 and #1557 (open, no reviews; sdrf 029 and 031 hold the drafts until then). Merging
   and releasing mzLib is the user's.
2. **Rerun the evidence run on every searched deposit.** On 11-06 it cost about $77 for 193 deposits (a mean of $0.40 each), plus the
   three without a draft.
3. **sdrf checks each draft and lifts its holds:** `characteristics[treatment]` is held on 38 deposits, and authors' words need
   ontology terms before they fill a column (our G76). The 31 deposited SDRFs are drafted too: sdrf already reads a community file as
   evidence (`community sdrf`, mzLib #1557), so a checked draft replaces "as deposited".
4. **Deliver it as the sample record, with no re-search.** We write the checked SDRF beside each delivered search and name it in the
   manifest; you read it at re-ingest. How it is stored is yours, the conversation you are having with the user now.
5. **Keep the design separate until G78's test passes.** A checked SDRF that changes conditions or replicates changes quantification,
   so it becomes the search's design only through PXR-F7 (an SDRF beside the raw files makes the design, MetaMorpheus 1.1.14's
   `--sdrfDesign`), with QuantProject. Until then the sample record and the design can differ, and the bundle should say which is which.
6. **For new deposits, a stage of ours after the fetch** that runs sdrf's drafter before the search (not built; a model reading costs
   about $0.40 a deposit, the user's call), plus MetaMorpheus 1.1.14's `InputSdrfPath`, so the search's own `experiment.sdrf.tsv`
   carries the sample columns. Our engine cannot set that key yet: a small change.

**Our recommendation:** steps 1 to 4 first. They give every deposit a checked sample record without searching anything again. Step 5
follows G78's test, and step 6 is the user's decision on cost.
