# 013 - PXReprise to dataRepo - 2026-10-05 - DATAREPO-72 is built: start time, model and serial per run in qc_report.json, as read (PXReprise 52cd138); live at our next release

## What changes for you

1. **DATAREPO-72 is built** (PXReprise `52cd138`, 169 offline tests pass). It is not released yet; we will tell you
   the release and the first deposit that carries it.
2. **Each run's entry in `qc_report.json` gains up to four keys**, beside `run_minutes`:

   | key | value |
   |---|---|
   | `start_time` | the reader's acquisition start, unconverted |
   | `instrument_model` | the model's name, e.g. `Orbitrap Fusion` |
   | `instrument_model_accession` | its PSI-MS accession, e.g. `MS:1002416`, only when the reader gives one |
   | `instrument_serial` | e.g. `FSN10189` |

   - **A key is written only for a value the reader gave.** A missing key means "not read"; there is never an empty
     string and never a null.
   - **Reading them never fails QC.** A file that cannot be read gets none of them, as before.
3. **Where they come from:**
   - mzLib 1.0.593's `SourceFile`, which `LoadAllStaticData` already fills (mzLib #1349). There is no second pass
     over the file.
   - We QC only `.raw`, so today the reader is always mzLib's `ThermoRawFileReader` and the time is
     `FileHeader.CreationDate`.
4. **The time trap, handled as you asked:**
   - A RAW header time has no zone. It is written with none, e.g. `2021-03-16T12:09:07.375`, and never shifted.
   - A time a reader gives as UTC would end in `Z`; mzLib's mzML reader does that.
   - `02b_qc/provenance.json` carries a note naming the reader and the field, and says the value is the
     instrument's local clock.
5. **Checked on real files** through mzLib 1.0.593 (mzLib's test data):

   | file | start_time | model | serial |
   |---|---|---|---|
   | `small.RAW` | 2005-07-20T14:44:22.377 | LTQ FT | SN06061F |
   | `sliced_ethcd.raw` | 2021-03-16T12:09:07.375 | Orbitrap Fusion | FSN10189 |
   | `05-13-16_cali_MS_60K-res_MS.raw` | 2016-05-13T14:21:12.093 | LTQ Orbitrap Velos | SN03001B |

   None of the three carries a model accession, so that key is left out for them.
6. **0.32.0 is safe with it.** `runs.py` reads the QC entry with `.get()`, so the new keys are ignored until your C#
   ingester reads them.
7. **For the 91 deposits already searched:** we agree that only a re-fetch can supply their times, and that the call
   is aging's.

No new ask.
