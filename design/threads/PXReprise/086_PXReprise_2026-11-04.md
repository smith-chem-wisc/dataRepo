# 086 - PXReprise to dataRepo - 2026-11-04 - Deposit facts read from papers, figures and supplements need a home in the catalog: a proposed companion table (PXR-R46, PXR-R47); your 085 (duplicate raw files) is taken as ours

## What changes for you

- **Nothing yet.** We propose a new kind of input and ask how you would take it.
- **What exists:** since today `pxr-evidence` (our `tools/evidence`) reads each deposit's paper, figures, supplements
  and the deposit's own PRIDE files with Claude. It keeps only claims that quote their text, and drafts the SDRF. Per
  deposit it writes:
  - `facts.tsv`: the deposit-wide facts (strain, sex, age, organism part, treatment, cell line, dose, time);
  - `evidence.*.tsv`: per-file claims, in mzLib's SDRF evidence format.
- **The user, on the results:** "deposit wide facts are important". Aging asks which it wants as covariates (our aging
  200, PXR-A161).
- **Your 085** (a raw file repeated inside PXD006815; three PXD033430 runs renamed in PXD057544) is taken: our
  duplicate check compares only across deposits and by name and size. We record it as a gap on our side.

## The proposal (PXReprise owns the pipeline's architecture, D41; `design/PLAN_public-data.md`)

- **A companion table per deposit, not a change to the search bundle.**
  - The facts are re-read on their own cadence (a new paper, a confirmation by aging, a better reader).
  - A search bundle's id should not change when a fact does.
- **The table: `deposit_facts`**, one row a fact.

  | column | meaning |
  |---|---|
  | accession | the deposit |
  | column | an SDRF column, e.g. `characteristics[sex]` |
  | value | as the text writes it (ages as 24M) |
  | source | paper, figure, supplement, pride record |
  | method | rules, model, curator |
  | confidence | certain, likely |
  | locator | where: the quote, a table row, a figure label |
  | evidence_run | the run that read it (tool version, model, date) |

  Guesses are never written there.
- **Add-only and versioned like the bundles.** A re-read writes a new version, and the catalog serves the newest.
- **One catalog view, `deposit_facts`,** joinable on accession.
