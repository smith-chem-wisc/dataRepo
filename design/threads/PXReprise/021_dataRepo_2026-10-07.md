## 1. datarepo 1.3.0 has never ingested a 1.1.12 search

- **What / where:** datarepo 1.3.0 (`187a42e`, ingest path `cs-1.1.0`, mzLib 1.0.593 inside). It was tested on

- **How to use:** nothing new. `datarepo ingest --json` as today.
- **Recommendation: adopt now, with one check first.** Ingest ONE 1.1.12-searched deposit into a scratch store
  before the batch delivers 1.1.12 results to aging's store. Send us the envelope and the dataset's findings, and
  the output folder path. We diff it against the same deposit's 1.1.11 bundle. Ask: **PXR-R3**.
- **Traps:** a new or renamed column in 1.1.12's `.psmtsv` or quant tables would surface as an ingest refusal or as
  findings, not as a crash in the search. We have not read 1.1.12's writers for this, so we claim nothing either way.

## 2. Ingest reads modifications from `<work_root>/mm_settings/<version>`, and a missing folder fails silently

- **What / where:** `Ingester.cs:270-273`. When `--mm-settings` is not given, ingest reads `Mods/*.txt` and
  `Data/ptmlist.txt` from `<work_root>/mm_settings/<manifest metamorpheus value>`. Today that is
  `F:/aging_data/mm_settings/1.1.11` (1.1.9 and 1.1.10 are also there).
- **How to use:** put the 1.1.12 install (or at least its `Mods/` and `Data/`) at `F:/aging_data/mm_settings/1.1.12`,
  and write `metamorpheus: 1.1.12` in the manifest entry of every deposit searched on 1.1.12.
- **Recommendation: adopt now**, before the first 1.1.12 ingest. Ask: **PXR-R4**.
- **Traps:** a missing folder is **not an error** (`ModList.cs:437`). The registry is empty, every modification is
  stored as a ProForma `[Info:...]` tag, and each is reported only as a finding. `ingest` still returns `ingested`, so
  the bundle looks fine. A manifest that still says 1.1.11 for a 1.1.12 search resolves against the wrong mod files.

## 3. 1.1.11 and 1.1.12 bundles will key five modification families differently

- **What / where:** mzLib 1.0.594's `Mods.txt` (shipped in 1.1.12) adds or changes Unimod references against 1.0.591's
  (shipped in 1.1.11). Added: `Myristoylation` on C/K (UNIMOD:45), `GG (Ubiquitination Site)` on K (UNIMOD:121) and
  `EQIGG (sumoylation (SMT-3) Site yeast)` on K (UNIMOD:846). Changed: `Decarboxylation` on D/E, from UNIMOD:914 to
  UNIMOD:1915. This is read off the file diff, not measured on a bundle.
- **How to use:** nothing to switch. It follows from item 2: a 1.1.12 search ingested against `mm_settings/1.1.12`.
- **Recommendation: not a pipeline change, but a decision for you and aging.** A store that holds both versions gives
  the same peptidoform two different keys across datasets for these mods. In 1.1.11 bundles, the three that had no
  reference were unresolved `[Info:...]`. Tell us whether the store will mix versions or whether older deposits are
  re-searched on 1.1.12. Ask: **PXR-R5**.
- **Other mixed-version trap:** 1.1.12 contains MetaMorpheus #2844 (iterative PEP training, on by default). Since 1.0.0
  datarepo records it in `pep:DEF-PEP`'s version key (`iterative on` / `off`). PEP and PEP-based counts are not
  comparable across 1.1.11 and 1.1.12 bundles. That is pep's change; we only label it.
