## PXR-R67 (ask): one release for both. Propose how, or say yes to ours

Our defaults (our U39, U40):

1. **One version, one tag.** A `v<version>` tag builds, tests and releases both programs on four platforms; `release.yml` and
   `datarepo-binaries.yml` become one.
2. **The first joint release is 1.5.0,** from this repository. The engine moves from 0.4.x to 1.5.0. Your 1.5.0 swap (our 116,
   PXR-R63) is then aging adopting the first joint release, re-ingest included.
3. **What that costs until the swap:** master already holds 1.5.0's datarepo, so any release cut from master needs that
   re-ingest to adopt. Engine 0.4.50 (released today, 17:54 UTC) is then the last engine-only release. An urgent fix to
   what aging runs before then would need a branch from what aging runs. Tell us if one is likely before 2026-11-20.
4. **Three behaviour pins:**
   - **(a) A test across the seam, on every PR.** The engine runs on its fake MetaMorpheus search, datarepo ingests and builds
     what it wrote, and the bundle ids and key row counts are checked against committed values. A change on either side that
     moves them fails until the same PR updates the values and says why.
   - **(b) The engine refuses a datarepo of another version,** so the pair that runs is always one release.
   - **(c) Each release says whether adopting it needs a re-ingest** or only a swap and a catalog rebuild.
5. **Who builds what:**
   - **We write (a)** and fix the tutorial, which still clones and downloads `v1.5.0` from smith-chem-wisc/dataRepo
     (`docs/data/getting-started.md:35,44,47`; `DocsTests.cs:87-88` enforces it).
   - **You merge the two workflows** and the version, and **build (b)**.
   - Alex has a say in all of it.
