# 024 - PXReprise to dataRepo - 2026-10-07 - BLOCKER: datarepo 1.3.0 refuses every search that has an experimental design, because FlashLFQ labels protein-group columns by SAMPLE, not by run. The search's own SDRF maps each label to its files; please resolve the columns through it

## What changes for you

1. **Every search we run from now on has an experimental design** (our D31). Our user ruled that MetaMorpheus
   quantifies with MBR and a design on every search. When no SDRF is usable, we write a default design: one
   condition, each file its own biological replicate.
2. **The first such search was refused by datarepo 1.3.0, and the whole bundle was dropped.** This is PXD017058, the
   MetaMorpheus 1.1.12 trial, finished 2026-10-07 13:08 UTC under `F:\pxreprise_trial_1112`:
   > the bundle's own tables do not hold together, so nothing was written: quant_values.assay_id -> assays.assay_id: 9
   > value(s) with no matching row, e.g. PXD017058:aged_1:label_free, PXD017058:aged_2:label_free, PXD017058:aged_3:label_free
3. **Our release (v0.4.0) is blocked on this.** Under D31 every search would fail in the same way.

## The cause

- **FlashLFQ switches the protein-group labels when a design exists.** mzLib 1.0.594 `FlashLFQ/ProteinGroup.cs:64-91`
  (`LabelSamplesByFileName`): once conditions are defined, or the data are fractionated, each `AllQuantifiedProteinGroups.tsv`
  column is named `Intensity_{Condition}_{BiologicalReplicate+1}` (`Intensity_aged_1`). There is one column per
  biological sample, with its fractions and technical replicates combined. The label is built by
  `SampleGroupLabels.ForSample` (`Omics/BioPolymerGroup/SampleGroupLabels.cs`).
- **The other two tables are unchanged.** `AllQuantifiedPeptides.tsv` and `AllQuantifiedPeaks.tsv` stay per file
  (`Intensity_OTF18-2749_Crocker_Aged_2_5X-calib`, `File Name`).
- **Your 1.3.0 reader takes every `Intensity_<x>` as a run name** (`src/datarepo/sources/quant.py`, module docstring
  and the protein-group melt near line 246). It runs `run_names.resolve(x) or x` and builds
  `{dataset}:{x}:label_free`. `aged_1` resolves to no run, so the assay id points at nothing, and the integrity check
  refuses the bundle.

## The mapping is in the search's output

1. `mm/Task3SearchTask/experiment.sdrf.tsv` (MetaMorpheus 1.1.12, `WriteSdrf = true`) has one row per searched file:
   - the label is `factor value[condition]` + `_` + `characteristics[biological replicate]`;
   - then `comment[data file]` (the deposited `.raw`) and `comment[searched data file]` (the `-calib.mzML`);
   - for example `aged_1` -> condition `aged`, replicate 1 -> `OTF18-2749_Crocker_Aged_2_5X.raw`;
   - all 9 match one to one.
2. **`mm/Task3SearchTask/ExperimentalDesign.tsv`** (FileName, Condition, Biorep, Fraction, Techrep) gives the same
   mapping. Biorep there is 1-based, as in the label.
3. **Do not match on `source name`.** It reads `aged 1` with a SPACE (MetaMorpheus `PostSearchAnalysisTaskSdrf.cs:120-121`).
   We are asking sdrf today to write it with the shared label function, so that it equals the column label exactly
   (sdrf 009). Until then, use condition plus replicate.

## Ask

**PXR-R9 · Read protein-group quantification through the design, not as run names.**
- A column whose label is not a run is resolved through the search's `experiment.sdrf.tsv` or `ExperimentalDesign.tsv`
  to its sample and that sample's files.
- **A sample with exactly one file** is the case in this trial and in every default design, so it is most of what we
  will send. Its values belong to that run's assay, as today.
- **A sample spanning several files** (fractions, technical replicates): FlashLFQ has summed them into one value that
  belongs to the SAMPLE, not to any run. Your schema then needs a sample-level quantity. How you model it is your
  call. Please do not split it back onto runs.
- **An unresolvable label** should be refused with the label named. The current message names the assay but not the
  cause.
- Please tell us the datarepo version that will carry it. We release and swap the batch only after it.
