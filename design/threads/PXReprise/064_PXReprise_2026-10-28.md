## What it does

- **Contributions are stored beside the bundles,** in `<store>/_contributions/<id>/contribution.json` (A1). They are
  outside `_engine/` on purpose. `SelectArtefacts` drops an artefact whose bundle was re-searched or whose schema
  version differs (`Catalog.cs:1066-1074`). Either rule would silently lose an AI result at the next release.
- **The id is the full sha256 of exactly what the submitter stated** (A2): no time, no install, no schema or runner
  version. A save checks that the cited catalog exists (by the id it holds, not its file name) and that it holds every
  basis bundle (A4).
- **Every catalog build loads every contribution** (A9).
  - The tables are created only when there is at least one, by the census rule. So no catalog id moves, and there is
    no `CatalogVersion` bump.
  - `catalog_id` gains one line; `release_id` gains none (A10).
  - A re-searched deposit is shown in `contribution_basis`, not dropped (A11).
  - A retraction or a supersession is a new contribution; nothing is deleted (A12).
  - A `--release` build lists the ids it carries. A later build refuses if one is missing (A13).
  - `--keep` never prunes a catalog that a contribution cites (A14).
- **The server keeps a public record of every call itself** (A18; the user: "the server side should independently
  choose to keep any interaction" and "this is a public repo. no question is private").
  - It is hash-chained JSONL in `<store>/_sessions/` and holds the tool, the arguments, the catalog, the outcome, the
    tables touched, and hashes of the answer and its rows. It holds no prompt, no model text and no person.
  - Every client is told at `initialize`, through MCP `instructions`.
  - Each answer carries `session_call`. Builds load `sessions` and `session_calls`, and releases carry them like
    contributions.
- **`datarepo_save_result` is served only with `mcp --contributions <inbox>`** (A15).
  - Cited queries are copied from the record as observed. An agent can state neither an observed query nor its own
    client (A16).
  - `datarepo contribute inbox|accept|reject` is the operator's step. `accept` checks every observed query again
    against the record on disk.
- **`describe()` reports contributions and public sessions when a catalog has any.** `mcp --show-prior` (the user's
  opt-in) adds `prior_work` to each `sql` answer.
- **Unchanged without the new options or data:**
  - The tool list stays exactly the three tools.
  - Every answer and every catalog id stays as before.
  - The parity fixtures pass untouched.
