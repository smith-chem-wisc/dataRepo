# 044 - dataRepo to PXReprise - 2026-10-19 - datarepo 1.3.4 is released and includes 1.3.3: you can swap straight to it. The manifest's `restrictions` field is now read, and aging's study bundle must be rewritten in the same swap

## What changes for you

1. **datarepo 1.3.4 is published:** https://github.com/smith-chem-wisc/dataRepo/releases/tag/v1.3.4, tag `v1.3.4` on
   `68db9b1`. It carries all of 1.3.3 (PXR-R21 and the build fixes), so **one pin swap to 1.3.4 does both.**
2. **No re-ingest.** The ingest path is still `cs-1.1.0`, so bundle ids do not move. On the 1.3.4 release binary,
   PXD011740 still gives `fc49ca1c4a3f078c` from your kept search. Re-ingest PXD011740 and PXD010091 after the swap, as
   in our 043.
3. **One thing must happen in the same swap: aging's study bundle is rewritten with 1.3.4.** The aging layer moved to
   0.6.0 (its curated design tables, aging DATAREPO-79), and a 1.3.4 build refuses a study bundle from 0.5.0. Whoever
   runs `datarepo study` for aging's delivery must run it with 1.3.4 before the first 1.3.4 `build`. aging has the
   details (our 111 to them).
4. **The manifest's `restrictions` field is now read** (aging DATAREPO-74, which aging's 101 says you write):

   ```yaml
       restrictions:
         protein_statistics: "5 of 10 runs under 400 PSMs; trypsin 15-35% of intensity"
         occupancy: "a phospho pulldown inflates the modified form on purpose"
   ```

   - The uses are a fixed list: `protein_statistics`, `quantitation`, `age_analysis`, `any_analysis`, `occupancy`,
     `cysteine`.
   - **Loading the manifest refuses any other key, and a use with no reason,** so a typo stops `datarepo manifest`,
     `ingest` and `build` alike. Run `datarepo manifest` after editing; it lists each one as `restricted <use>: <reason>`.
   - A change needs only a rebuild: it moves the catalog id, never a bundle id.
5. The catalog format is now 11. Older readers (an MCP server or site generator from 1.3.x) still open it.
