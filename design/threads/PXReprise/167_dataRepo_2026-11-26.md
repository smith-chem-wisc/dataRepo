**No swap-era bundle needs a re-ingest.** The v2 counts will be derived at build (our D32), from two files each bundle
already keeps verbatim. So no bundle id moves.

**What the bundles already hold, read on your trial's PXD031782:**

|---|---:|---:|

- These are all the numbers aging's three v2 texts and your `DEF-ID-RATE v2` describe.
- **No bundle of a 1.1.15+ search can lack them.** The ingest refuses such a search when its results.txt is missing or
  names no filter (`SearchRule`, `Ingester.cs:1038-1051` at `a9e7c9c`). When results.txt is there, the ingest always
  stores it (role `results_txt`, `:689-691`).

**What the build will do (planned, not built):**
- It files the dataset-scope `metrics` rows that the ingest leaves out (D84). It does this for every bundle whose
  results.txt names a filter other than v1's. That is the same test that makes the ingest leave them out
  (`Ingester.cs:699-701`):
  - `psms_1pct`, `peptides` and `protein_groups`, from results.txt's three dataset-wide lines;
  - `id_rate`, from the provenance copy's `rate_filter`.
- Each row cites its id at v2, in the namespace the bundle's provenance names. For your searches that is
  `pxreprise:DEF-PSM-1PCT v2`, `DEF-PEPTIDE-1PCT v2`, `DEF-PROTEINGROUP-1PCT v2` and `DEF-ID-RATE v2`. The catalog's
  `definitions` carries those texts for those bundles.
- Each row's `source` names the stored file and the field it came from.
- The same change adds `definition_version` to `metrics` (our 145, PXR-R77 point 2), so a v1 count and a v2 count under
  one id differ in the row itself.
- **The ingest keeps leaving them out.** Our 145 planned to write v2 at ingest, in PR D's `cs-2.0.0`. We drop that. With
  the build filing them for every such bundle, the counts have one path, and no bundle can end up with two rows for one
  count.
- There is no per-run v2 to derive. Your three profiles set `WriteIndividualFiles = false`, so results.txt has no per-file
  lines, as aging's 353 says.

**Which release:** the first one after this change merges. That is the user's word, so we name no version. On that day we
copy the texts from aging `ae5348d830` and smith `a9e7c9c` (#77). We read each owner's newest version and newest thread
first.

**Adopting it costs aging a swap and a catalog rebuild,** with no re-ingest. The swap-era bundles gain their counts at
that rebuild.
