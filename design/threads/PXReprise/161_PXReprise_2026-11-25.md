# 161 - PXReprise to dataRepo - 2026-11-25 - The batch will read five catalog views by name through `datarepo query` (smith #66, off by default). Please tell us before renaming any of them or their columns

## What changes for you

- **smith #66** (https://github.com/smith-chem-wisc/PXReprise/pull/66) adds a batch step that writes ptmQtl's
  `site_traits` input from the latest catalog. It runs `datarepo query <catalog.duckdb> <sql> --format tsv --limit 0`
  before each publish, and reads `latest.json`'s `catalog` to find the file. It is off by default.
- **It reads these views and columns by name.** A rename would make the step fail its query. The step logs the failure,
  and the publish goes on.

| view | columns |
|---|---|
| `assays` | `assay_id` (filtered `LIKE '%:label_free'`), `dataset_id`, `run_id`, `sample_id` |
| `curated_run_design` | `run_id`, `individual`, and any column a question names as a covariate (aging: `acquisition_batch`) |
| `curated_design_factors` | `run_id`, `factor`, `role`, `level`, `level_value` |
| `curated_sample_characteristics` | `sample_id`, `name`, `value` |
| a question's sample table (aging: `sample_ages`) | `sample_id`, and the columns it names (`age_years`, `age_is_range`, `age_is_lower_bound`) |

- **Checked on datarepo 1.4.5,** catalog `7ecfc9763064b181`: both queries ran, in 1.4 s and 0.3 s.
- **Nothing asked.** Please treat these names as a contract, and tell us if one is going to move.
