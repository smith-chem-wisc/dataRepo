# 081 - PXReprise to dataRepo - 2026-11-03 - MetaMorpheus #2909 (a search names its identification filter): the results.txt count lines your reader takes change shape under it

## What changes for you

- **Nothing today.** #2909 is in review, unreleased, and its default (`Thresholds`) writes results.txt exactly as
  MetaMorpheus 1.1.13 does.
- **When a MetaMorpheus release carries #2909, our next profile names a filter** (`IdentificationFilter =
  "PepQValueElseQValueNotch"`; G30, D57). Every bundle searched under it then has different count lines.
- **One ask, PXR-R43**, below.

## 1. What results.txt says under a named filter

Your 078 says your reader takes only the lines that begin `All target ... with q-value <= 0.01` or
`<file> - Target ...`. Under a named filter, each level's lines read like this:

```
Identification filter for PSMs: pep q-value < 0.01
All target PSMs with pep q-value < 0.01: N
Identification filter for peptides: pep q-value < 0.01
All target peptides with pep q-value < 0.01: N
All target protein groups with pep q-value < 0.01: N
```

- **The comparison is strict** (`<`, not `<=`), and the threshold is printed unrounded.
- **The value can be** `pep q-value`, `q-value notch`, `q-value`, or two of them joined by ` or ` when PEP trained
  for some matches and not others.
- **When PEP was not trained** for a digestion agent (or, in a semi- or non-specific search, a cleavage-specificity
  category), one more line sits between the filter line and the count:
  `PEP filtering was requested, but PEP was not computed for the Arg-C PSMs, so they were filtered by q-value notch.`
  The filter line then names each group:
  `pep q-value < 0.01 for trypsin; q-value notch < 0.01 (PEP not trained: 200 PSMs) for Arg-C`.
- **The per-file lines** (`<file> - Target PSMs with ...`) change the same way: the value and the `<`.

## 2. Ask

- **PXR-R43:** will your reader take `All target PSMs with <value> < <threshold>: N` (and the per-file and
  peptide forms) when a bundle's search named its filter? Or should it read the filter from the
  `Identification filter for ...` line and leave the count lines alone? Either is fine for us. We need it
  before the first profile that names a filter, which waits on a MetaMorpheus release, so there is no date.
