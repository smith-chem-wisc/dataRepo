## The cause, in one paragraph

With a design, MetaMorpheus/FlashLFQ labels the **protein-group** columns by sample: `Intensity_{Condition}_{Biorep}`,
plus `SpectralCount_`, `CountOccupancy_` and `IntensityOccupancy_` with the same label (mzLib `ProteinGroup.cs`,
`SampleGroupLabels.ForSample`). A sample's fractions and technical replicates are combined into one column set.
`AllQuantifiedPeptides.tsv` and `AllQuantifiedPeaks.tsv` stay labeled per file (`Intensity_<file>-calib`).

Your reader, `dotnet/src/DataRepo.Ingest/Readers.cs:216-218`, takes every `Intensity_<x>` as a run name. So `all_1`
becomes the assay `PXD...:all_1:label_free`, which no run carries, and the bundle check refuses the whole deposit.

## What a fix needs to do (R9, restated)

- Map each protein-group label to its files through the search's own `ExperimentalDesign.tsv`, or through
  `experiment.sdrf.tsv`. MetaMorpheus writes both into `Task3SearchTask` whenever a design was used.
  - label = `Condition + "_" + Biorep`;
  - files = the design rows with that Condition and Biorep;
  - the run = the file name minus `-calib.mzML` / `.mzML`, as your peptide reader already strips it.
- **A sample with one file (variant A, every default design):** its values belong to that run's assay. This alone
  unblocks the whole aging batch.
- **A sample with several files (variant B, fractions or technical replicates):** the value is a sample-level
  quantity. Never split it onto runs. Store it at the sample level, or leave it out with a finding. That choice is
  yours; QuantProject owns what it means.
- **No design file and per-file labels:** keep today's behaviour (the baseline).
- **Label not found in the design:** refuse with that message, not with an assay-key mismatch.
- **One trap in the SDRF:** `source name` reads `all 1` (a space, from MetaMorpheus `PostSearchAnalysisTaskSdrf.cs:120-121`),
  while the column label is `all_1`. Build the label from `factor value[condition]` and
  `characteristics[biological replicate]`, never from `source name` (open with sdrf as PXR-F3).
- **A working reference:** our QC payload does exactly this mapping in `src/PXReprise/Search/ProteinGroupColumns.cs`
  (one file, then the run; several files, then no run value).
