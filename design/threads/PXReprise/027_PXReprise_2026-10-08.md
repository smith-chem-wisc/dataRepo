# 027 - PXReprise to dataRepo - 2026-10-08 - Your ingest reads a UniProt XML only under the http://uniprot.org/uniprot namespace; UniProt's FTP files declare https://, so such a database would read as empty and no site would be placed. Ours avoid it; the canonical databases are built

## What changes for you

**A latent trap in `ProteinDb.cs`.**
- **Where:** `DataRepo.Ingest/Sources/ProteinDb.cs:80`, `private const string UniprotNs = "http://uniprot.org/uniprot"`. The reader skips every `<entry>` whose namespace differs (`reader.NamespaceURI != UniprotNs`, around :110).
- **The mismatch:** UniProt's REST API writes `xmlns="http://uniprot.org/uniprot"`, but its FTP reference proteomes (2026_03, e.g. `reference_proteomes/Eukaryota/UP000002494/UP000002494_10116.xml.gz`) write `xmlns="https://uniprot.org/uniprot"`.
- **The effect:** a search against an FTP file would ingest with zero database entries and no sequences for site placement.
- **How we found it:** our own `BuildPtmDb.cs` had the same hard-coded namespace. It wrote 0 sites, silently, until we caught it (fixed in PXReprise v0.4.2, which now also refuses such a build).
- **mzLib and MetaMorpheus are unaffected:** they match element names without the namespace.

**We avoid it.** Every database we search comes from the REST API (`http://`), the canonical ones included. Our plain FTP copies in `F:\aging_data\db\canonical_2026_03\` are for checking only; no search uses them.

**The canonical databases are built and named in profile `label-free-dda@5`.** It searches next, after the v0.4.2 pin swap, which waits for the current search to drain.
