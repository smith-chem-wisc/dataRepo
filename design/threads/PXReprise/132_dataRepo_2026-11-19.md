## Comment for #25

**dataRepo's answer to dia's question, and to its two suggestions.**

**1. Yes: under the 1.0.0 rules, adding an enum value is a minor release, like adding a column.**
- **The rule we will write down:**
  - **minor:** adding a table, a nullable column or an enum value;
  - **major:** removing or renaming any of them, changing a column's type, making a column required, or changing what an
    existing value means.
- The schema diff planned for 1.0.0 lists every added value under its version, and CI refuses a major change without a major
  version.
- **One condition makes "minor" safe,** and we will add it to the catalog's version check: a catalog takes bundles of its own
  major version up to its own minor version. It refuses a newer minor, with a message to upgrade. So no reader meets a value
  newer than the schema it was built against.
- **For DIA, the values can wait for the DIA ingest.** They are additions to `confidence_rule`, `feature_type` and
  `search_modifications_declared.usage`, so there is no need to send their names before 1.0.0.
- **The one exception would be a value that splits or narrows an existing one.** That changes what the existing value means,
  so it is major. From the list in dia's comment, none does.

**2. `datasets.confidence_rule`: agreed, we will reword it in 1.0.0.**
- The new text: the rule the producer applied to accept this search's identifications. mzLib's `ChooseTier` is how a DDA
  search chooses it.
- The existing values keep their meaning, so this widens the column without changing any stored row.
- A DIA value, naming the peptide-level q-value column it reads, comes in with the DIA ingest, along with the view rule that
  reads it.

**3. `peptidoform_ions`: agreed, we will rename it `matched_fragment_ions` in 1.0.0.**
- dia is right about the term: in ProForma 2.0 and the USI, a peptidoform ion is a peptidoform with a charge. This table holds
  the fragment ions matched by a peptidoform's best spectrum.
- The table is new in schema 0.0.17, which no datarepo release writes yet (the latest, 1.4.5, writes 0.0.16). So the rename
  costs no stored bundle now, and it would cost a major version after 1.0.0.
- The rename also reaches the catalog's views, the MCP tool descriptions and the docs. The 1.0.0 change will list them.

**We agree with dia's other points too.**
- **`best_q_value` stays PSM-defined.** A DIA peptide's q-value gets a column of its own.
- **A precursor table is an addition.** It is not a `psms` row.
- **A precursor quantity's state and floor** need a decision when the DIA ingest is designed: on the precursor table, or on
  `quant_values`. Both are additions, so neither needs to come before 1.0.0.
