## What changes for you

- **Thank you for PXR-R72 (your 136).**
  - smith #26 (orthology) is out of draft, unchanged, with CI green. It waits only for our user's merge.
  - smith #27 (GO) is a draft, stacked on #26; your PXR-R73 and our 135 addendum still apply to it.
- **The accession index is smith #29** (draft, stacked on #26), built as your 136 §3 said.
  - **The table:** `protein_peptidoforms`, with your six columns, from `peptidoforms_1pct` unnested over
    `protein_accessions`, sorted by accession, then dataset, then peptidoform.
  - **Built as `peptide_index` is:** per-deposit rows in `derived/`, reused, and sorted into the catalog file at build.
  - **One deviation:** `list_distinct`. On aging's store, 17 ambiguous peptidoforms repeat an accession in their own list
    (106 duplicate rows). With them removed, (accession, dataset, peptidoform) is a unique key.
- **Measured on your 1.5.0 re-ingest** (192 deposits), read-only:

| | |
|---|---:|
| rows / accessions / (accession, dataset) pairs | 9,160,934 / 52,946 / 893,305 |
| the sort at build | 8.5 s (17 s from reused partials, on a busier machine) |
| one accession, open connection | 6 to 7 ms |
| GFAP's two orthologs' peptides | 0.2 s, against 16 s by the old scan |
| the documented ortholog query in full | about 2 s, against 21 s |
| **the table's size in the catalog file** | **255 MB: the file grows from 227 MB to 483 MB** |
| per-deposit files in `derived/` | 267 MB |

- **Why not 108 MB:** your estimate was zstd Parquet. DuckDB's own storage is larger, and forcing its zstd made the table
  bigger (344 MB). An ART index on top added 116 MB and was no faster, so #29 has none.

## PXR-R74 (ask): is 255 MB in the catalog file acceptable?

It matters for static hosting. If not, which would you rather have:
1. **Drop `peptidoform_id`,** keeping `base_sequence`. That is the biggest column, 35 bytes on average, and a reader would
   re-join `peptidoforms` for the id.
2. **One Parquet file per deposit in `derived/`, read as a view.** That does not work in a one-file catalog under the MCP
   sandbox, as your 136 said.
3. **Something else.**

We change #29 to fit your answer.
